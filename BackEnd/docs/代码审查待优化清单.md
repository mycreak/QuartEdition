## 四、问题关联分析

> 以下问题在行为/链路上有因果或共享根因，应成组修复以避免碎片化。

---

### 链路 A：`asyncio.CancelledError` 被吞 → shutdown 延迟链

**根因**：多个模块的 `except Exception` 不区分 `CancelledError`，
shutdown cancel 信号被吞，Worker/Browser/WebSocket 全部延迟退出。

```
M7-H1 (fetcher)        BrowserFetcher._do_fetch() 吞 CancelledError
  │                        ↓ Worker cancel 被吞 → execute() 继续跑完
  ├── M7-H1 (fetcher)  ApiFetcher._request() 吞 CancelledError
  ├── M9-M1 (utils)    get_current_user() 吞 CancelledError
  ├── M6-H1 (routes)   websocket except Exception: pass 吞 CancelledError
  └── M1-M3 (app)      _sanitize_body except Exception 吞 KeyboardInterrupt
                           ↓
                    结果：shutdown 阶段所有 cancel 都失效
                          → BrowserPool.stop() 超时 30s
                          → playwright.stop() 等 30s
                          → 总关闭时间 ≥60s
```

| 关联问题 | 模块 | 修复优先级 |
|---------|------|----------|
| M7-H1 | crawler/fetcher.py | 🔴 最高 — 影响面最大 |
| M9-M1 | utils/auth.py | 🔴 |
| M6-H1 | routes/websocket.py | 🔴 |
| M1-M3 | app.py | 🟡 |

---

### 链路 B：shutdown 资源泄漏链

**根因**：关闭路径中异常未捕获 + 死锁/复活漏洞 → 数据库连接永不释放。

```
M1-H1 (app)         playwright.stop() 未 try/except
                       ↓ 异常 → 跳过 close_mysql/redis/mongodb
M8-H3 (background)  restart_dead_workers 在 shutdown 时复活 Worker
                       ↓ 新 Task 开始 execute() → 占用连接
M8-H5               stop() 无超时 → execute() 可能 10min+
                       ↓
                  结果：DB 连接池泄漏 + 进程长时间不退出
```

| 关联问题 | 模块 | 修复优先级 |
|---------|------|----------|
| M1-H1 | app.py | 🔴 |
| M8-H3 | background/worker.py | 🔴 |

```
                    ↓ 都是豆瓣 type_num，但 SQL AS 别名不同
M4-M4 (models)   CreditRead.person_id  vs  PeopleRead.id
                    ↓ 都是 person 主键，展平 vs 嵌套字段名分裂
M6-M2 (routes)   _summarize_task 仍取 subject_id 不取 douban_id
                    ↓ 存量任务兼容逻辑缺新字段 fallback
M7-M1 (crawler)  URL 模板 {subject_id} 占位符名歧义
```
