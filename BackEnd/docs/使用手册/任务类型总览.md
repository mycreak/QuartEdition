# 任务类型总览

> 最后更新：2026-05-18
>
> 本文档覆盖 Quart 后端爬虫调度系统中**全部 9 种任务类型**，包括其定义、数据流、产生的子任务关系、以及任务生命周期管理。

---

## 一、系统架构概述

```
┌─────────┐     ┌─────────┐     ┌──────────┐
│  Admin  │────▶│  Redis  │────▶│  Puller  │
│  POST   │     │  ZSET   │     │ (拉取到期 │
│ /tasks  │     │delay_queue│    │  任务)   │
└─────────┘     └─────────┘     └────┬─────┘
                                     │
                              asyncio.Queue
                                     │
                              ┌──────▼──────┐
                              │  BrowserPool │
                              │  (5 Worker)  │
                              └──────┬──────┘
                                     │ execute(task)
                              ┌──────▼──────┐
                              │   Crawler   │
                              │  (分派矩阵)  │
                              └──────┬──────┘
                                     │
                        ┌────────────┼────────────┐
                        │            │            │
                     MySQL       MongoDB       Redis
                   (电影/评论)   (评论正文)    (词云缓存)
```

**核心组件**：
| 组件 | 文件 | 职责 |
|------|------|------|
| Puller | [background/puller.py](../background/puller.py) | 从 Redis ZSET 拉取到期任务 → asyncio.Queue |
| Worker (BrowserPool) | [background/worker.py](../background/worker.py) | 5 个常驻协程，消费队列执行任务 |
| Monitor | [background/monitor.py](../background/monitor.py) | 采集指标、消费事件、失败写入 |
| Crawler | [crawler/__init__.py](../crawler/__init__.py) | 任务分派矩阵，编排 fetch→parse→store |
| Subtask | [crawler/subtask.py](../crawler/subtask.py) | 子任务注入器（ZADD Redis + INSERT history） |

## 二、任务分类体系

### 2.1 按执行引擎分类（task_category）

| category | 引擎 | 说明 |
|----------|------|------|
| `api` | ApiFetcher (aiohttp) | 请求 JSON API，轻量快速 (~0.5s) |
| `browser` | BrowserFetcher (Playwright) | 请求受保护的 HTML 页面，重资源 (~3.7s+) |

### 2.2 category 映射表

定义在 [services/task_history_service.py](../services/task_history_service.py) 的 `_CATEGORY_MAP`：

```python
_CATEGORY_MAP = {
    "movie_crawl":           "api",       # 榜单 JSON API
    "ai_review_summary":     "api",       # DeepSeek AI API 调用
    "ai_wordcloud":          "api",       # DeepSeek AI API 调用
    "review_crawl":          "browser",   # 长评列表 HTML 页
    "review_body_crawl":     "browser",   # 改为 JSON API，历史沿用 browser
    "comment_crawl":         "browser",   # 短评列表 HTML 页
    "movie_scrape_task":     "browser",   # 电影详情 HTML 页
    "movie_detail_crawl":    "browser",   # 电影详情 HTML 页（补爬）
    "director_crawl":        "browser",   # 演职人员 HTML 页
}
```

## 三、9 种任务类型详解

### 类型 1：`movie_crawl` — 电影 ID 补充

| 属性 | 值 |
|------|-----|
| **category** | `api` |
| **触发方式** | 管理端手动提交 (`POST /admin/tasks`) |
| **必要参数** | `type_num`（豆瓣类型编号）、`interval_id`（评分区间如 `"100:90"`） |
| **执行引擎** | ApiFetcher（aiohttp） |
| **副作用** | 写入 `douban_ids` 表 + 推进 `crawl_progress.ids_fetched` |
| **产生的子任务** | 无（仅收集 ID） |
| **失败策略** | 事务回滚，`ids_fetched` 不变，下次从同一 `start` 偏移重试 |

**数据流**：

```
POST /admin/tasks {type:"movie_crawl", type_num:11, interval_id:"90:80"}
  → ZADD Redis delay_queue
  → Puller 拉取 → Worker 执行
  → ① 确保 crawl_progress 占位行
  → ② 无缓存 → GET /j/chart/top_list_count → 写入 douban_total
  → ③ 按 ids_fetched 计算 start 偏移
  → ④ GET /j/chart/top_list?start=N&limit=20
  → ⑤ 原子事务: INSERT IGNORE douban_ids + UPDATE ids_fetched
```

**豆瓣类型与评分区间**：

定义在 [config/movie_type.py](../config/movie_type.py)：
- `TYPE_MAP`：24 种豆瓣类型（如 11=剧情、24=喜剧、1=纪录片...）
- `ACTIVE_INTERVALS`：`["100:90", "90:80", "80:70", "70:60"]`（生产环境只爬 4 档高分区间）

**⚠️ 易错点**：
- `start = ids_fetched`（而非 COUNT douban_ids），避免手动添加的 ID 干扰分页对齐
- `douban_ids` 写入和 `ids_fetched` 推进在**同一事务**中提交/回滚
- 即使多次提交同类型-区间的 `movie_crawl`，`ids_fetched` 也始终与实际 API 分页一致

### 类型 2：`movie_scrape_task` — 单部电影详情爬取

| 属性 | 值 |
|------|-----|
| **category** | `browser` |
| **触发方式** | 管理端手动提交 + 可作为 `movie_crawl` 后手工跟进 |
| **必要参数** | `douban_id`（豆瓣电影ID） |
| **可选参数** | `cookie_id`、`proxy_key`（不传则游客模式 + 直连） |
| **执行引擎** | BrowserFetcher（Playwright） |
| **副作用** | 写入 `movies`、`movie_genres`、`movie_regions`、`movie_ratings`；更新 `douban_ids.is_scraped=1` |
| **产生的子任务** | ✅ `director_crawl`（自动注入） |

**数据流**：

```
POST /admin/tasks {type:"movie_scrape_task", douban_id:"1295644", cookie_id:"...", proxy_key:"..."}
  → ① 构建身份（CookieManager + ProxyPool 解析 identity）
  → ② BrowserFetcher 爬详情页（最多 2 次重试，间隔 120~250s 随机）
  → ③ parse_movie_detail(html) → save_movie_basic(movie_id)
        写入: movies + movie_genres + movie_regions + movie_ratings
  → ④ UPDATE douban_ids SET is_scraped=1
  → ⑤ inject_subtask(type="director_crawl", douban_id, movie_id)  ← 自动子任务
```

**子任务关系**：

```
movie_scrape_task (parent)
    └── director_crawl (子任务，继承 admin_id + parent_task_id)
```

**⚠️ 易错点**：
- 详情页最多重试 2 次，间隔 120~250s 随机（避免触发豆瓣反爬）
- `save_movie_basic` 失败时不会注入 `director_crawl` 子任务
- `cookie_id` 和 `proxy_key` 均可选，不传时用游客模式 + ProxyPool 轮转

---

### 类型 3：`movie_detail_crawl` — 电影详情补爬

| 属性 | 值 |
|------|-----|
| **category** | `browser` |
| **触发方式** | 系统内部/管理端手动提交 |
| **必要参数** | `douban_id` |
| **执行引擎** | BrowserFetcher（Playwright） |
| **副作用** | 写入 `movies`（详情）+ `people` + `movie_credits`（演职人员） |
| **产生的子任务** | 无（演职人员已在本任务内解析写入） |

**数据流**：

```
  → ① BrowserFetcher 爬详情页 → parse_movie_detail
  → ② BrowserFetcher 爬 celebrities 页 → parse_personnel
  → ③ save_movies（含 crew 一并写入）
```

**与 `movie_scrape_task` 的区别**：
| 维度 | `movie_scrape_task` | `movie_detail_crawl` |
|------|---------------------|----------------------|
| 演职人员处理 | 不在本任务内，通过注入子任务完成 | 在本任务内 inline 完成 |
| 重试机制 | 2 次重试（120~250s 间隔） | 无重试 |
| 身份构造 | 支持显式 cookie+proxy | 游客模式 |
| 适用场景 | 首次爬取新电影 | 存量补爬（已有 douban_id 但缺详情/演职） |

### 类型 4：`review_crawl` — 长评摘要采集

| 属性 | 值 |
|------|-----|
| **category** | `browser` |
| **触发方式** | 管理端手动提交 (`POST /admin/tasks`) |
| **必要参数** | `douban_id`（或 `subject_id`） |
| **可选参数** | `movie_id`、`cookie_id`、`proxy_key`、`pages`（翻页数） |
| **执行引擎** | BrowserFetcher（Playwright） |
| **副作用** | `INSERT IGNORE movie_review`（status='pending'），每次取最多 5 条新评论 |
| **产生的子任务** | 无（`review_body_crawl` 由管理端单独批量下发） |

**数据流（v3 顺延模式）**：

```
  → ① 查询 movie_review 已有数量 → 计算顺延 offset
  → ② 反爬等待 8~20s（随机）
  → ③ GET /subject/{douban_id}/reviews?sort=hotest&start={offset}
  → ④ parse_review_list(html) → 取最多 5 条新评论
  → ⑤ INSERT IGNORE movie_review (status='pending')
  → ⑥ 最多翻页 2 次（每页 20 条中取够 5 条为止）
```

**⚠️ 易错点**：
- `offset` 对齐到 `page_size` 的整数倍（如已有 58 条 → offset=40）
- 每次只取 5 条新评论（`review_crawl_max_new` 配置），避免单次任务耗时过长
- 最多翻 2 页（60 条中取 5 条），防止 Worker stuck
- **不会自动生成 `review_body_crawl` 子任务**，长评正文需进入管理端批量下发

---

### 类型 5：`review_body_crawl` — 长评正文爬取

| 属性 | 值 |
|------|-----|
| **category** | `browser`（历史沿用，实际使用 ApiFetcher） |
| **触发方式** | 管理端单个/批量提交 (`POST /admin/tasks`) |
| **必要参数** | `douban_id`、`review_id` |
| **可选参数** | `movie_id`、`title`、`author`、`cookie_id`、`proxy_key` |
| **执行引擎** | ApiFetcher（aiohttp → `/j/review/{id}/full` JSON API） |
| **副作用** | MongoDB 写入长评全文 + `UPDATE movie_review SET status='done'/'failed'` |
| **产生的子任务** | ✅ `ai_review_summary`（当 done 数 ≥ `ai_summary_min_reviews` 时触发） |

**数据流**：

```
POST /admin/tasks {type:"review_body_crawl", douban_id, review_id, title, author}
  → ① 去重判断：MongoDB 已存在 → UPDATE status='done'（幂等）
  → ② ApiFetcher → GET /j/review/{review_id}/full
  → ③ parse_review_full(json) → 提取 html、纯文本、votes
  → ④ MongoDB upsert + UPDATE movie_review SET status='done'
  → ⑤ _check_and_trigger_ai_summary(movie_id)
        └── 当 done 数 ≥ cfg.ai_summary_min_reviews(默认5)
            → inject_subtask(type="ai_review_summary")
```

**批量下发机制（前端）**：

```
管理端 "任务提交" 页 → 选择 "长评正文抓取"
  → 弹出电影选择器（仅显示有 pending 长评的电影）
  → 勾选要爬的单篇/多篇长评
  → 前端循环调用 POST /admin/tasks（每篇一个独立任务）
  → 后端有 Redis 去重（key: crawler:dedup:review_body:{review_id}，TTL=1h）
```

**子任务关系**：

```
review_body_crawl (最后一篇 done 触发)
    └── ai_review_summary（幂等：已生成过的 movie 不再触发）
```

**⚠️ 易错点**：
- 幂等设计：MongoDB 已存在的长评直接标记 `done`，不重复请求
- AI 总结触发条件：done 数量 ≥ `ai_summary_min_reviews`（默认 5 条）且 `review_summary` 表中无 `done` 记录
- Redis 去重 key `crawler:dedup:review_body:{review_id}` 防止 1 小时内重复提交

---

### 类型 6：`comment_crawl` — 短评抓取

| 属性 | 值 |
|------|-----|
| **category** | `browser` |
| **触发方式** | 管理端手动提交 (`POST /admin/tasks`) |
| **必要参数** | `douban_id`（或 `subject_id`） |
| **可选参数** | `movie_id`、`cookie_id`、`proxy_key`、`pages`（默认 1 页 = 20 条） |
| **执行引擎** | BrowserFetcher（Playwright） |
| **副作用** | MongoDB `short_comments` 写入 + 清除 Redis 词云缓存 |
| **产生的子任务** | ✅ `ai_wordcloud`（入库成功后自动注入） |

**数据流**：

```
  → ① 查询 MongoDB 已有短评数量 → 计算顺延 offset
  → ② 反爬等待 3~10s（随机）
  → ③ GET /subject/{douban_id}/comments?start=N&limit=20&status=P
  → ④ parse_comments(html) → 去重
  → ⑤ 翻页间等待 5~15s（随机）
  → ⑥ MongoDB 批量写入 → 清除 Redis wordcloud:movie:{movie_id}
  → ⑦ inject_subtask(type="ai_wordcloud", movie_id)  ← 自动子任务
```

**子任务关系**：

```
comment_crawl (parent)
    └── ai_wordcloud（清除旧缓存后重新生成）
```

**⚠️ 易错点**：
- `start_offset` 从 MongoDB 已有短评数计算，向下取整到 `page_size` 的整数倍
- 翻页失败不中断整批：单页 HTML 保存到 `data/` 目录，报 item 级失败继续下一页
- 全部页解析失败则抛异常标记整个任务失败

---

### 类型 7：`director_crawl` — 演职人员爬取

| 属性 | 值 |
|------|-----|
| **category** | `browser` |
| **触发方式** | ① `movie_scrape_task` 自动注入（主要）；② 管理端手动提交（存量补录） |
| **必要参数** | `douban_id`、`movie_id` |
| **执行引擎** | BrowserFetcher（Playwright） |
| **副作用** | 事务原子写入 `people` + `movie_credits`（导演/演员/编剧/制片/美术/音乐等） |
| **产生的子任务** | 无 |

**数据流**：

```
  → ① BrowserFetcher 爬 /subject/{douban_id}/celebrities
  → ② parse_personnel(html) → 全部角色类型
  → ③ storage.save_crew(movie_id, crew)
        └── 事务: INSERT IGNORE people + INSERT movie_credits
```

**⚠️ 易错点**：
- 解析不到演职人员时不抛异常（`logger.warning` + 正常返回），因为部分条目确实无演职员页
- 写入使用事务保证 `people` 和 `movie_credits` 的原子性

---

### 类型 8：`ai_review_summary` — AI 长评总结

| 属性 | 值 |
|------|-----|
| **category** | `api` |
| **触发方式** | `review_body_crawl` 完成后自动触发（不可手动提交） |
| **必要参数** | `movie_id` |
| **执行引擎** | ApiFetcher（DeepSeek AI API） |
| **副作用** | 写入 `review_summary` 表（full_summary + review_tags JSON） |
| **产生的子任务** | 无 |

**数据流**：

```
  → ① 幂等检查：review_summary 已有 done → 跳过
  → ② INSERT review_summary SET status='pending'（防并发）
  → ③ 拉取 top 20 长评正文（按 useful_count 排序）
  → ④ 调用 DeepSeek AI → 生成综合总结 + 5~10 个标签
  → ⑤ UPDATE review_summary SET status='done', full_summary, review_tags
```

**AI Prompt 配置**：

定义在 [scripts/ai_prompts.py](../scripts/ai_prompts.py)：
- `REVIEW_SUMMARY_SYSTEM_PROMPT`：综合分析 + 标签提取，输出严格 JSON
- `REVIEW_SUMMARY_USER_PROMPT_TPL`：将长评文本注入模板

**⚠️ 易错点**：
- 先插入 `pending` 再处理，防止并发重复生成
- AI 生成失败时标记 `status='failed'`，可重来（`pending`/`failed` 状态均可重试）
- 截取每篇长评最多 800 字（`ai_summary_max_chars` 配置），防止 token 超限

---

### 类型 9：`ai_wordcloud` — AI 短评词云

| 属性 | 值 |
|------|-----|
| **category** | `api` |
| **触发方式** | `comment_crawl` 完成后自动注入 + 管理端手动提交 |
| **必要参数** | `movie_id` |
| **执行引擎** | ApiFetcher（DeepSeek AI API） |
| **副作用** | Redis 缓存 `wordcloud:movie:{movie_id}`（JSON: words + total_words + updated_at） |
| **产生的子任务** | 无 |

**数据流**：

```
  → ① MongoDB 拉取最多 100 条短评全文
  → ② 不足 10 条 → 跳过
  → ③ 调用 DeepSeek AI → 提取 30~50 个关键词（含权重 0~200）
  → ④ Redis: SET wordcloud:movie:{movie_id} (无 TTL，由 comment_crawl 清除)
```

**AI Prompt 配置**：

定义在 [scripts/ai_prompts.py](../scripts/ai_prompts.py)：
- `COMMENT_WORDCLOUD_SYSTEM_PROMPT`：提取 30~50 个评价关键词 + 权重
- `COMMENT_WORDCLOUD_USER_PROMPT_TPL`：将短评文本注入模板

## 四、子任务关系全景图

```
┌─────────────────────────────────────────────────────────┐
│                    管理端手动提交入口                      │
│           POST /admin/tasks（task_routes.py）            │
│  movie_crawl │ movie_scrape_task │ review_crawl          │
│  comment_crawl │ review_body_crawl │ director_crawl      │
│  ai_wordcloud │ movie_detail_crawl                       │
└──────────┬──────────────────────────────────────────────┘
           │
           ▼
    ┌──────────────┐
    │  Redis ZSET  │
    │ delay_queue  │
    └──────┬───────┘
           │
    ┌──────▼───────┐
    │   Puller     │
    └──────┬───────┘
           │
    ┌──────▼───────┐
    │  5 Workers   │──── execute(task)
    └──────┬───────┘
           │
    ┌──────▼───────────────────────────────────────────────────┐
    │                    Crawler 分派矩阵                        │
    │                                                          │
    │  movie_crawl ──────────────▶ douban_ids（无子任务）       │
    │                                                          │
    │  movie_scrape_task ────────▶ movies + genres/regions     │
    │       │                         │                        │
    │       │  自动注入               │                        │
    │       └──▶ director_crawl ──▶ people + movie_credits     │
    │                                                          │
    │  review_crawl ──────────────▶ movie_review (pending)     │
    │       │                                                  │
    │       │  管理端批量下发                                    │
    │       └──▶ review_body_crawl ──▶ MongoDB reviews         │
    │                  │                    │                   │
    │                  │   done≥5时自动注入  │                   │
    │                  └──▶ ai_review_summary ──▶ review_summary│
    │                                                          │
    │  comment_crawl ─────────────▶ MongoDB short_comments     │
    │       │                         │                        │
    │       │  入库后自动注入          │                        │
    │       └──▶ ai_wordcloud ────▶ Redis 词云缓存             │
    │                                                          │
    │  movie_detail_crawl ─────────▶ movies + people + credits │
    │       (演职人员 inline 处理，无子任务)                     │
    └──────────────────────────────────────────────────────────┘
```

**自动子任务链总结**：

| 父任务 | 子任务 | 触发条件 |
|--------|--------|----------|
| `movie_scrape_task` | `director_crawl` | 电影基础信息入库成功后 |
| `comment_crawl` | `ai_wordcloud` | 短评入库成功后（即使只有 1 条也触发） |
| `review_body_crawl` | `ai_review_summary` | done 数 ≥ `ai_summary_min_reviews`（默认 5）且未生成过总结 |

> **注意**：`ai_review_summary` 不开放手动提交，仅由 `review_body_crawl` 完成后自动触发。`ai_wordcloud` 既自动触发也开放手动提交。

## 五、任务生命周期

### 5.1 状态机

```
                  ┌──────────┐
                  │ submitted │  ← inject_subtask() 写入 Redis + history
                  └────┬─────┘
                       │ Puller 拉取 → Worker 开始执行
                  ┌────▼─────┐
                  │  running  │  ← Monitor 消费 STARTED 事件更新
                  └────┬─────┘
                       │
          ┌────────────┼────────────┐
          │            │            │
    ┌─────▼──────┐ ┌──▼───┐ ┌──────▼──────┐
    │    done    │ │failed│ │  cancelled   │
    └────────────┘ └──┬───┘ └─────────────┘
                      │
                ┌─────▼──────┐
                │ task_failure│  ← Monitor 写入失败记录
                │ (pending)   │
                └─────┬──────┘
                      │ 管理员认领
                ┌─────▼──────┐
                │  claimed    │
                └─────┬──────┘
                      │ 重爬 / 放弃 / 解决
                ┌─────▼──────┐
                │  resolved   │
                └────────────┘
```

### 5.2 关键生命周期环节

| 环节 | 负责组件 | 说明 |
|------|----------|------|
| **创建** | `inject_subtask()` | ZADD Redis + INSERT task_history（status=submitted） |
| **拉取** | Puller | 从 Redis ZSET 按 score（到期时间）拉取 → asyncio.Queue |
| **开始** | Worker → Monitor | Worker 发送 `STARTED` 事件 → Monitor 消费更新 status=running |
| **结束** | Worker → Monitor | `SUCCESS` → done；`FAILURE` → failed + 写 task_failures；`CANCELLED` → cancelled |
| **认领** | 管理端 API | `POST /admin/failures/<id>/claim`（原子 WHERE status='pending'） |
| **重爬** | 管理端 API | `POST /admin/failures/<id>/retry` → 重新 Push 到 Redis |

## 六、关键配置参数

| `ai_summary_max_reviews` | 10 | AI 总结最多使用的长评数 |
