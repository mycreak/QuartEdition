# 权限管理系统文档

> 总览：9 条权限编码 → `permissions` 字典表 → `user_permissions` N:N 关联表 → `@require_permission` 装饰器拦截

***

## 一、权限枚举（9 条）

预置在 `scripts/seed_auth.py` 中，写入 `permissions` 表。

| 编码 | 名称 | 说明 | 保护的端点 |
|------|------|------|-----------|
| `user:manage` | 用户管理 | 创建/禁用/恢复/删除用户，分配/撤销权限 | `GET/POST /admin/users`、`POST /admin/users/<id>/permissions` |
| `crawler:task:read` | 任务只读 | 查看爬取进度、任务历史 | `GET /admin/tasks`、`/task-history`、`/task-history/<id>` |
| `crawler:task:write` | 任务提交 | 提交爬虫任务 | `POST /admin/tasks` |
| `crawler:failure:manage` | 失败管理 | 认领/释放/解决/重试失败任务 | 6 个 `/admin/failures/*` 端点 |
| `movie:manage` | 电影管理 | 编辑/上下架 movies/people/credits/genres/regions/rating | `PATCH /admin/movies/<id>`、`POST /admin/movies/<id>/publish`、`unpublish`、`credits`、`genres`、`regions`、`PUT .../rating` |
| `movie:read` | 查看电影数据 | 只读访问电影详情 | `GET /admin/movies`、`GET /admin/movies/<id>` |
| `comment:read` | 评论查看 | 查看长评/短评列表 | `GET /admin/reviews`、`GET /admin/comments` |
| `comment:manage` | 评论管理 | 长评/短评上下架管理 | `POST /admin/reviews/<id>/publish`、`unpublish`、`POST /admin/comments/<id>/publish`、`unpublish` |
| `system:monitor` | 系统监控 | 查看实时状态/队列/日志/限流事件 | `GET /admin/status`、`/tasks/queue`、`/logs`、`/rate-limit-events` |

> 权限编码使用 `{领域}:{操作}` 命名规范。推荐分配组合：
> - **运维管理员**：`crawler:task:read` + `crawler:task:write` + `crawler:failure:manage` + `system:monitor`
> - **只读审计**：`crawler:task:read` + `system:monitor`
> - **内容编辑**：`movie:read` + `movie:manage` + `comment:read` + `comment:manage`

## 二、数据库表结构

### 2.1 users — 用户表

```sql
CREATE TABLE users (
    id            INT           NOT NULL AUTO_INCREMENT,
    username      VARCHAR(64)   NOT NULL,
    password_hash VARCHAR(256)  NOT NULL COMMENT 'bcrypt 哈希',
    display_name  VARCHAR(64)   NOT NULL DEFAULT '',
    is_active     TINYINT(1)    NOT NULL DEFAULT 1 COMMENT '1=启用 0=禁用',
    created_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at    DATETIME      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_username (username)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 2.2 permissions — 权限字典表

```sql
CREATE TABLE permissions (
    code        VARCHAR(32)  NOT NULL,
    name        VARCHAR(64)  NOT NULL COMMENT '权限名称',
    description VARCHAR(256) NOT NULL DEFAULT '' COMMENT '权限说明',
    PRIMARY KEY (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 2.3 user\_permissions — 用户-权限 N:N 关联表

```sql
CREATE TABLE user_permissions (
    user_id         INT         NOT NULL,
    permission_code VARCHAR(32) NOT NULL,
    granted_by      INT         NOT NULL DEFAULT 0 COMMENT '授权管理员 ID',
    granted_at      DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (user_id, permission_code),
    CONSTRAINT fk_up_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    CONSTRAINT fk_up_perm FOREIGN KEY (permission_code) REFERENCES permissions(code) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

> 联合主键 `(user_id, permission_code)` 天然防重复；`ON DELETE CASCADE` 确保用户删除后关联记录自动清理

## 四、管理员角色划分

系统中没有"角色"表，权限直接挂载在用户上。按拥有权限的集合来区分：

| 身份        | 判断方式                               | 行为                            |
| --------- | ---------------------------------- | ----------------------------- |
| **超级管理员** | DB 中拥有全部 9 条 `user_permissions` 记录 | 可做一切操作，包括创建/禁用用户、分配/收回权限 |
| **普通管理员** | DB 中拥有部分 `user_permissions` 记录     | 只能访问拥有权限对应的端点                  |
| **普通用户**  | DB 中 `user_permissions` 为 0 条      | 只能访问 `/auth/*` 和 `/user/*` 端点 |
| **已禁用用户** | `users.is_active = 0`              | 任何 token 都会被拒绝                |

## 五、超级管理员给普通管理员赋权/收回

### 5.1 分配权限（grant）

```
POST /admin/users/<user_id>/permissions
Authorization: Bearer <超级管理员的 JWT>
Content-Type: application/json

{
  "permission_codes": ["movie:read", "movie:manage", "crawler:manage"]
}
```

**逻辑链路：**

```
user_routes.py:assign_permissions()
  │
  ├─→ ① @require_permission("user:manage") — 只有拥有 user:manage 的管理员才能操作
  │
  ├─→ ② Pydantic 校验
  │     UserPermissionAssign(
  │       user_id=user_id,
  │       permission_codes=["movie:read", "movie:manage", ...],
  │       granted_by=g.user_id,       ← 当前登录的管理员 ID
  │     )
  │     → @field_validator("permission_codes")
  │       检查每个 code 是否在 VALID_PERMISSION_CODES 白名单中
  │       不在白名单 → raise ValueError
  │
  ├─→ ③ AuthService.grant_permissions(data)
  │     for each code in permission_codes:
  │       先查是否已存在（幂等）
  │       不存在 → INSERT INTO user_permissions
  │       已存在 → skip
  │     日志: "权限分配完成: user_id=... granted=3/5 by=1"
  │
  └─→ 返回 {"granted": 3, "total": 5}
```

**核心代码：**

```python
# services/auth_service.py : grant_permissions()
async def grant_permissions(self, data: UserPermissionAssign) -> int:
    count = 0
    for code in data.permission_codes:
        existing = await self.db.find_one("user_permissions", {
            "user_id": data.user_id,
            "permission_code": code,
        })
        if existing:
            continue                                         # 已存在 → 跳过（幂等）
        await self.db.insert("user_permissions", {
            "user_id": data.user_id,
            "permission_code": code,
            "granted_by": data.granted_by,                    # 记录谁授权的
        }, return_id=False)
        count += 1
    return count
```

### 5.2 收回权限（revoke）

> ⚠️ 当前 API 层**没有**收回权限的 HTTP 端点（只有 `POST /admin/users/<id>/permissions` 做赋权）。
> `AuthService.revoke_permission()` 方法已实现，但未注册路由。

**Service 层已可用的方法：**

```python
# services/auth_service.py : revoke_permission()
async def revoke_permission(self, user_id: int, permission_code: str) -> bool:
    await self.db.execute_raw(
        "DELETE FROM user_permissions WHERE user_id = %s AND permission_code = %s",
        (user_id, permission_code),
    )
    return True
```

**如果前端需要收回功能，建议新增端点：**

```python
# routes/admin/user_routes.py（建议新增）
@user_bp.route("/users/<int:user_id>/permissions/<permission_code>", methods=["DELETE"])
@require_permission("user:manage")
async def revoke_permission(user_id: int, permission_code: str):
    from services.auth_service import _get_auth_service
    from models.user_permission import VALID_PERMISSION_CODES

    if permission_code not in VALID_PERMISSION_CODES:
        return jsonify({"error": f"无效的权限编码: {permission_code}"}), 400

    svc = _get_auth_service()
    await svc.revoke_permission(user_id, permission_code)
    return jsonify({"success": True, "message": f"权限 {permission_code} 已收回"})
```

## 六、权限校验底层 — @require\_permission 装饰器

```
utils/auth.py:require_permission(permission_code)
  │
  ├─→ get_current_user()
  │     │
  │     ├─→ Authorization: Bearer <token> → 提取 JWT
  │     ├─→ AuthService.verify_token(token) → user_id
  │     └─→ AuthService.get_user(user_id).is_active → 未禁用
  │
  ├─→ 未登录 → return 401
  │
  ├─→ AuthService.check_permission(user_id, code)
  │     │
  │     └─→ SELECT 1 FROM user_permissions
  │           WHERE user_id= AND permission_code=
  │         → 有记录 = True, 无记录 = False
  │
  ├─→ 无权限 → return 403 {"error": "无权限: {code}"}
  │
  └─→ 通过 → g.user_id = user_id → 执行原始 handler
```

**核心代码：**

```python
# utils/auth.py
def require_permission(permission_code: str):
    def decorator(func):
        @wraps(func)
        async def wrapper(*args, **kwargs):
            user_id = await get_current_user()
            if not user_id:
                return jsonify({"error": "未登录或登录已过期"}), 401

            svc = _get_auth_service()
            if not await svc.check_permission(user_id, permission_code):
                return jsonify({"error": f"无权限: {permission_code}"}), 403

            g.user_id = user_id
            return await func(*args, **kwargs)
        return wrapper
    return decorator
```

## 七、超级管理员种子

`scripts/seed_auth.py` 在首次部署或重置时执行：

```bash
python scripts/seed_auth.py
```

**种子行为：**

1. 建三张表（`users` / `permissions` / `user_permissions`）— `CREATE TABLE IF NOT EXISTS`
2. 插入 9 条权限记录 — `INSERT ... ON DUPLICATE KEY UPDATE`
3. 创建 `admin` 用户 — `INSERT ... ON DUPLICATE KEY UPDATE`
4. 给 `admin` 分配全部 9 条权限 — `INSERT IGNORE`

**可配环境变量：**

| 变量               | 默认值                                             | 说明       |
| ---------------- | ----------------------------------------------- | -------- |
| `ADMIN_USERNAME` | `admin`                                         | 超级管理员用户名 |
| `ADMIN_PASSWORD` | `admin123`                                      | 超级管理员密码  |
| `JWT_SECRET`     | `quart-edition-dev-secret-change-in-production` | 生产环境必须修改 |

## 八、白名单校验

`models/user_permission.py` 中 `VALID_PERMISSION_CODES` 作为守卫层：

```python
VALID_PERMISSION_CODES = {
    "user:manage",              # 用户管理
    "crawler:task:read",        # 任务只读
    "crawler:task:write",       # 任务提交
    "crawler:failure:manage",   # 失败管理
    "movie:manage",             # 电影管理
    "movie:read",               # 查看电影数据
    "comment:read",             # 评论查看
    "comment:manage",           # 评论管理
    "system:monitor",           # 系统监控
}
```

**校验时机：**

- 在 `UserPermissionAssign` Pydantic 模型的 `@field_validator("permission_codes")` 中校验
- 如果传入的 code 不在白名单内 → 立即返回 400，不会写入 DB

**新增权限的步骤：**

```
① 在 seed_auth.py 的 PERMISSION_CODES 和 SQLS 中新增一条
② 在 models/user_permission.py 的 VALID_PERMISSION_CODES 中新增
③ 在对应的路由 handler 上加上 @require_permission("new:code")
④ 重新运行 seed_auth.py（或手动 INSERT 到 permissions 表）
```

> **新增权限后部署**：
> 运行一次 `seed_auth.py` 即可将新权限写入 `permissions` 表，然后通过 `POST /admin/users/<id>/permissions` 为新管理员分配新权限。

## 十、快速运维 SQL

```sql
-- 查看某个用户拥有的权限
SELECT u.username, up.permission_code, up.granted_at, up.granted_by
FROM user_permissions up
JOIN users u ON u.id = up.user_id
WHERE u.id = 2;

-- 查看拥有某个权限的所有用户
SELECT u.id, u.username, up.granted_at
FROM user_permissions up
JOIN users u ON u.id = up.user_id
WHERE up.permission_code = 'movie:read';

-- 查看某个用户是否有 'movie:manage' 权限
SELECT 1 FROM user_permissions
WHERE user_id = 2 AND permission_code = 'movie:manage';

-- 统计每个权限有多少用户
SELECT permission_code, COUNT(*) AS user_count
FROM user_permissions
GROUP BY permission_code
ORDER BY user_count DESC;

-- 禁用用户（立即生效，现有 JWT 即刻失效）
UPDATE users SET is_active = 0 WHERE id = 2;

-- 删除用户（CASCADE 自动清理 user_permissions）
DELETE FROM users WHERE id = 2;
```

## 十一、已知问题

| 问题                 | 说明                                                                                         | 建议修复                                             |
| ------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| **无收回权限的 HTTP 端点** | `AuthService.revoke_permission()` 已实现，但路由层没有 `DELETE` 端点                                   | 新增 `DELETE /admin/users/<id>/permissions/<code>` |
