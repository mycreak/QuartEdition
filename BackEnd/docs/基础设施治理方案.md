## 二、已实施的改进

### 2.1 Worker 执行前随机 Jitter ✅

**问题**：Puller 批量弹出任务后，5 个 Worker 瞬间全部抢走同时执行，在豆瓣视角表现为 N 倍并发请求。

**方案**：每个 Worker 从队列取到任务后，在 `execute()` 之前插入随机睡眠，5 Worker 自然错峰。

**代码**：[background/worker.py](../../background/worker.py)

```python
jitter = random.uniform(
    puller_config.worker_jitter_min,    # 默认 120s
    puller_config.worker_jitter_max,    # 默认 300s
)
await asyncio.sleep(jitter)
```

**配置**：[config/puller_config.py](../../config/puller_config.py) — pydantic-settings，环境变量 `PULLER_WORKER_JITTER_MIN` / `PULLER_WORKER_JITTER_MAX` 可覆盖。

### 2.2 DatabaseLayerV2 ContextVar 隔离 ✅

**问题**：`_database_type` 是普通 Python 属性（共享可变状态），`review_service.py` 在 `set_database("mongodb")` 后 `await` 出让事件循环期间，其他请求读到 `MONGODB` 类型，导致 `users` 表查找失败 → 401。

**修复**：`_database_type` 改为 `contextvars.ContextVar`——每个 asyncio 任务持有独立的类型副本。

**代码**：[db/database_v2.py](../../db/database_v2.py#L170)

```python
class DatabaseLayerV2:
    def __init__(self):
        self._database_type = contextvars.ContextVar("db_type", default=None)

    def _get_type(self):
        val = self._database_type.get()
        if val is None:
            val = DatabaseType.MYSQL
            self._database_type.set(val)
        return val
```

### 2.3 CookieManager 多账号管理 ✅

**旧问题**：`CookieManager` 模块已完整实现但从未被初始化，`IdentityManager` 初始化失败，所有爬虫退化为游客模式。

**修复**：[app.py](../../app.py) startup() 中在 `init_crawler` 之前调用 `init_cookie_manager()`。

**核心组件**：[crawler/cookie_manager.py](../../crawler/cookie_manager.py) — 账号状态机 (active ↔ suspicious → banned)，`_save_metadata()` 已改为 `asyncio.to_thread` 异步写入。

### 2.4 IdentityManager — Cookie + IP 显式绑定 ✅

**设计**：[crawler/identity.py](../../crawler/identity.py)

```
Proxy(key="1.2.3.4:3128", region="CN") → Cookie(allowed_regions=["CN"])
Proxy(key="5.6.7.8:3128", region="JP") → Cookie(allowed_regions=["JP"])
```

三次约束检查在 `resolve()` 中完成：

| # | 约束 | 检查方式 |
|---|------|---------|
| 1 | Cookie 限定 IP 属地 | `proxy.region in account.allowed_regions` |
| 2 | 地区内 1 对 N | 不做限制（同 region 内随意） |
| 3 | 每 IP 只服务一个 Cookie | ProxyPool 轮转自然保证 |

### 2.6 爬虫架构重构 ✅

**旧流程**：movie_crawl 一个任务打包"获取 ID → 创建子任务 → 爬取详情"三个职责。

**新流程**：

```
① movie_crawl → 榜单 API → INSERT IGNORE douban_ids 表（ID 资产持久化）
② 管理员认领 douban_id → 显式指定 cookie_id + proxy_key
③ movie_scrape_task → Worker → BrowserFetcher.fetch(url, identity)
④ 失败 → task_failures(snapshot) 现场快照
⑤ Monitor 全程感知 cookie_id + proxy_key
```

**新增表**：[douban_ids](../../docs/数据库设计&使用/数据库设计.md#douban_ids)

## 四、爬虫反爬策略全景

```
┌─────────────────────────────────────────────────────────────────┐
│ 第1层 — User-Agent + Headers                                    │
│   BrowserFetcher: 5 种 Chrome/Firefox UA 随机轮换               │
│   ApiFetcher: 标准 Chrome 126 UA + 常见 Header                  │
│                                                                 │
│ 第2层 — 请求节流                                                │
│   ZSET cooldown: 相邻任务间隔 2s（入库层面）                     │
│   Worker jitter: 2~5min 随机（执行层面）                         │
│   BROWSER_SEMAPHORE=2: 同时最多 2 个 Playwright 页面            │
│                                                                 │
│ 第3层 — IP 代理轮换                                             │
│   ProxyPool 状态机: UNKNOWN→ALIVE↔SUSPICIOUS→BANNED            │
│   管理端 API: 查看/添加/封禁/验证                                 │
│   proxy_fetch_enabled: 免费代理抓取开关（.env 可控）              │
│                                                                 │
│ 第4层 — Cookie + IP 绑定                                        │
│   IdentityManager: cookie_id + proxy_key 显式绑定                │
│   多账号 CookieManager: active ↔ suspicious → banned 状态机     │
│   管理端 7 个 Cookie 管理 API                                    │
│                                                                 │
│ 第5层 — 挑战页处理                                              │
│   SHA-512: wait_for_timeout(3000) 自动完成                      │
│   "检测到有异常请求": 触发代理重试                               │
└─────────────────────────────────────────────────────────────────┘
```
