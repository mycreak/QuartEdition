## 一、设计介绍

### 1.1 设计目标

基于用户行为（想看/在看/看过/收藏/评论）自动构建个性化标签画像，结合电影多维度标签，实现 **CV 自适应内容推荐**——在「精准匹配已知偏好」和「探索未知领域」之间自动平衡。

### 1.2 架构全景

## 二、电影多维标签体系

### 2.1 十大维度

每部电影从两张数据源提取标签，覆盖 **10 个维度**：

| 维度 | 英文 | 数据源 | 标签示例 | confidence | 权重 |
|------|------|--------|----------|:--:|:--:|
| 年代 | `era` | `movies.release_year` | 1990s年代 | 1.0 | 0.3 |
| 地区 | `region` | `movie_regions + regions` | 中国 / 美国 | 1.0 | 0.4 |
| 导演 | `director` | `movie_credits + people` | 吕克·贝松 | 1.0 | 1.0 |
| 演员 | `actor` | `movie_credits + people` (top 5) | 汤姆·汉克斯 | 1.0 | 0.8 |
| 豆瓣分类 | `genre` | `movie_genres + crawl_progress` | 剧情 / 科幻 | 1.0 | 0.6 |
| 整体风格 | `overall` | `movie_style + movie_style_tag` (AI) | 温馨感人 | 0.0~1.0 | 0.7 |
| 剧情风格 | `plot` | `movie_style + movie_style_tag` (AI) | 反转惊悚 | 0.0~1.0 | 0.7 |
| 画面风格 | `visual` | `movie_style + movie_style_tag` (AI) | 冷色调 | 0.0~1.0 | 0.7 |
| 叙事风格 | `narrative` | `movie_style + movie_style_tag` (AI) | 非线性叙事 | 0.0~1.0 | 0.7 |
| 节奏风格 | `pacing` | `movie_style + movie_style_tag` (AI) | 快节奏 | 0.0~1.0 | 0.7 |

- **豆瓣维度**（前 5 个）：数据精确，`confidence=1.0`
- **AI 维度**（后 5 个）：由 DeepSeek 自动分析生成，`confidence=0.0~1.0`

### 2.2 演员位置衰减

演员按豆瓣排序取 top-5，越靠前的演员被认为越重要：

| 排名 | 衰减系数 |
|:--:|:--:|
| 第 1 名 | 1.00 |
| 第 2 名 | 0.85 |
| 第 3 名 | 0.70 |
| 第 4 名 | 0.55 |
| 第 5 名 | 0.40 |

### 2.3 电影标签权重公式

每个标签的综合权重：

```
tag.weight = dim_weight × position_decay × confidence
```

其中：
- `dim_weight`：维度基础权重（见上表）
- `position_decay`：仅 actor 维度生效，其余维度为 1.0
- `confidence`：豆瓣维度为 1.0，AI 维度为 0.0~1.0

## 三、用户画像构建（评分引擎）

### 3.1 评分公式

用户对一部电影执行操作后，按以下公式计算分差：

```
delta = action_weight × tag.weight
```

其中 `action_weight` 为操作基础权重：

| 操作 | action_weight | 说明 |
|------|:--:|------|
| 想看 | 1.0 | 最低权重 |
| 在看 | 1.2 | |
| 看过 | 2.0 | |
| 收藏 | 1.5 | 独立于观看状态 |
| 评论 | 3.0 | **最高权重**（需先标记看过），见下方 `rating_factor` 调节 |

> **v1.1 新增** — 评论评分调节因子（2026-05-29）

评论操作的 effective_weight 受用户打分调节：

```
effective_weight = action_weight × rating_factor(rating)
```

其中 `rating_factor` 为线性映射函数：

| 评分 | factor（默认配置） | effective_weight | 语义 |
|:--:|:--:|:--:|------|
| ⭐⭐⭐⭐⭐ | +1.00 | +3.00 | 强烈喜欢，大幅加分 |
| ⭐⭐⭐⭐ | +0.50 | +1.50 | 比较喜欢，中等加分 |
| ⭐⭐⭐ | 0.00 | 0.00 | 中性，不改变画像 |
| ⭐⭐ | -0.25 | -0.75 | 不太喜欢，降低该类型 |
| ⭐ | -0.50 | -1.50 | 反感，显著降低该类型 |
| 不评分 | 0.00 | 0.00 | 不改变画像 |

配置项（`config_score_weight` 表，热加载）：

| config_key | 默认值 | 说明 |
|------------|:--:|------|
| `comment.rating_neutral` | 3.0 | 中性点 |
| `comment.rating_factor_max` | 1.0 | 5星因子值，effective = action_weight × rating_factor_max |
| `comment.rating_factor_min` | -0.5 | 1星因子值（保守非对称） |

**设计理由**：差评惩罚设为 5 星的一半（-0.5 vs +1.0），因为「不喜欢」比「喜欢」更难量化——用户打 1 星可能因为电影烂，也可能因为"类型不对胃口"。后续可根据数据热调整。

每次操作对每个标签产生一条 `delta`，累加到 `user_tag_score` 表：

```
user_tag_score[user_id][dimension][label].score += delta
```

### 3.2 示例

用户 A 标记「看过」电影《肖申克的救赎》，该电影标签：

| 标签 | 维度 | weight | action_weight | delta |
|------|------|:--:|:--:|:--:|
| 剧情 | genre | 0.6 | 2.0 | **1.20** |
| 弗兰克·德拉邦特 | director | 1.0 | 2.0 | **2.00** |
| 蒂姆·罗宾斯 | actor | 0.8 | 2.0 | **1.60** |
| 1990s年代 | era | 0.3 | 2.0 | **0.60** |
| 美国 | region | 0.4 | 2.0 | **0.80** |
| 温馨感人 | overall | 0.7×0.9 | 2.0 | **1.26** |
| **总得分** | | | | **7.46** |

### 3.3 时间衰减

查询用户画像时，推荐系统使用 **衰减版**（`decayed=True`），历史操作越久远，贡献越低：

| 时间窗口 | 衰减系数 |
|----------|:--:|
| 0 ~ 30 天 | 1.0 |
| 30 ~ 90 天 | 0.8 |
| 90 ~ 180 天 | 0.5 |
| 180 天以上 | 0.2 |

衰减系数作为乘数作用于每条 `tag_deltas_json`：

```
effective_score = Σ (原始 delta × 时间衰减系数)
```

## 四、CV 自适应推荐算法

### 4.1 变异系数（CV — Coefficient of Variation）

对每个维度，收集用户所有标签分数后计算：

```
CV = σ / μ    （标准差 / 均值）
```

| CV 值 | 含义 | 策略 |
|-------|------|------|
| CV > 0.5 | 用户在该维度有明显偏好 | **精准匹配** |
| CV ≤ 0.5 | 用户在该维度偏好分散或无数据 | **随机探索** |

**特殊规则**：
- 该维度 ≤ 1 个标签 → CV = 0（样本不足，强制探索）
- 均值 μ < 0.01 → CV = 0（分数太低无意义）

### 4.2 精准模式（CV > threshold）

```
movie_score = Σ user_tag_score[dimension][label] × tag.confidence
```

即：候选电影的每个标签，乘以用户对该标签的历史偏好分数，再乘以 AI 可信度。偏好越明确，匹配分越高。

### 4.3 探索模式（CV ≤ threshold）

```
movie_score = Σ random(0, 1) × dim_weight
```

即：对该维度的每个标签随机赋分，乘以维度权重。引入随机性，帮助用户发现新领域。

### 4.4 推荐流程

```
输入: user_id, top_n(默认 10)
  │
  ├─ ① 加载用户画像（衰减版）
  │    └─ user_tag_score 为空 → 冷启动兜底
  │
  ├─ ② 计算各维度 CV
  │    └─ 标记 CV > 0.5 的维度为「精准」，其余为「探索」
  │
  ├─ ③ 召回候选池
  │    └─ movies WHERE is_published=1
  │    └─ 排除已「看过」且未回滚的电影
  │    └─ 最多 200 部
  │
  ├─ ④ 批量加载电影标签（6 次 JOIN 查询）
  │
  ├─ ⑤ 逐部打分
  │    └─ 精准维度 → 匹配用户标签分数
  │    └─ 探索维度 → 随机加权
  │
  ├─ ⑥ 按 score 降序 → top_n
  │
  └─ ⑦ 补全评分信息 → 返回 JSON
```

### 4.5 批量查询优化

候选池最多 200 部，不逐部调用 `MovieContextService.build()`（否则 200×6=1200 次 SQL），而是一次性批量 JOIN：

| 查询 | SQL 次数 |
|------|:--:|
| movies 基础信息 | 1 |
| 地区标签 | 1 |
| 导演标签 | 1 |
| 演员标签 top-5（窗口函数） | 1 |
| 豆瓣分类标签 | 1 |
| AI 风格标签 | 1 |
| **合计** | **6** |

## 五、冷启动策略

当用户无任何行为数据（`user_tag_score` 为空）时：

```
按 movie_ratings.average 降序，返回 top_n 部已上架电影
```

即按豆瓣评分降序推荐热门电影作为兜底。

## 八、特点总结

| 特点 | 说明 |
|------|------|
| **无需训练** | 基于规则 + 实时计算，无冷启动等待（系统冷启动用豆瓣评分兜底） |
| **CV 自平衡** | 偏好在某一维度越集中 → 越精准匹配；越分散 → 越随机探索 |
| **时间衰减** | 最近的行为权重更高，推荐不陈旧 |
| **A/B 实验友好** | 所有权重存于 config 表，改一行生效，无需发版 |
| **批量查询** | 200 部候选池仅 6 次 SQL，非逐部 1200 次 |
| **幂等** | 种子数据 `ON DUPLICATE KEY UPDATE`，重复导入不报错 |
| **跨维度** | 10 维标签覆盖结构化元数据 + AI 生成语义标签，比单纯「看过类似」更全面 |
