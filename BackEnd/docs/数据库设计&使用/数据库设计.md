## 一、MySQL

### 1.1 关系总览

```
users ──1:N── user_permissions ──N:1── permissions

users ──1:N── task_history ──1:N── task_failures

douban_ids ──N:1── task_history

movie_review ──N:1── movies

movies ──1:1── movie_ratings
movies ──1:N── movie_genres ──N:1── (type_num 常量)
movies ──1:1── movies_history          （版本历史，每行记录一次变更）
movies ──1:N── movie_genres_history    （类型变更历史）
movies ──1:N── movie_regions_history   （地区变更历史）
movies ──1:N── movie_regions ──N:1── regions
movies ──1:N── movie_credits ──N:1── people
movies ──1:N── movie_credits_history   （演职人员变更历史）

people ──1:N── people_history          （人员信息变更历史）

crawl_progress (独立，按 (type_num, interval_id) 索引)
```

### 1.2 表定义

CREATE TABLE users (
  id            INT           NOT NULL AUTO_INCREMENT,

#### douban\_ids — 豆瓣电影 ID 资产表

```sql
CREATE TABLE douban_ids (
  douban_id     VARCHAR(32)   NOT NULL PRIMARY KEY COMMENT '豆瓣电影ID',
  title         VARCHAR(128)  NOT NULL              COMMENT '电影名',
  source        VARCHAR(32)   NOT NULL DEFAULT 'dashboard_api'
                    COMMENT '来源: dashboard_api / manual',
  type_num      INT           DEFAULT NULL          COMMENT '电影类型编号',
  interval_id   VARCHAR(16)   DEFAULT NULL          COMMENT '评分区间',
  admin_id      INT           DEFAULT NULL          COMMENT '认领人 user_id',
  is_acquired   TINYINT(1)    NOT NULL DEFAULT 0    COMMENT '是否已被认领',
  is_scraped    TINYINT(1)    NOT NULL DEFAULT 0    COMMENT '0=未爬 1=已成功爬取',
  acquired_at   DATETIME      DEFAULT NULL,
  task_id       BIGINT        DEFAULT NULL          COMMENT '关联 task_history.id',
  created_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_acquired (is_acquired),
  INDEX idx_scraped (is_scraped),
  INDEX idx_task (task_id),
  INDEX idx_source (type_num, interval_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

生命周期状态机：

```
is_scraped=0, is_acquired=0  → 未认领（列表默认展示）
is_scraped=0, is_acquired=1  → 已认领，排队爬取中
is_scraped=1, is_acquired=1  → 终态：已爬取完成（列表隐藏，不可释放/重认领）
```

数据流：

```
movie_crawl → 榜单 API → INSERT IGNORE douban_ids (is_acquired=0, is_scraped=0)
管理员认领 → acquire → UPDATE is_acquired=1, admin_id=N
movie_scrape_task 成功 → UPDATE is_scraped=1（终态）
release → UPDATE is_acquired=0（仅限 is_scraped=0 且 admin_id=self）
```

## 三、Redis

### 3.1 `crawler:delay_queue`（ZSET）

```
Key:  crawler:delay_queue
类型: ZSET
Score: execute_at（unix timestamp）
Value: 任务 JSON 字符串

示例:
  1778308252.7  →  {"id": 46484014642499580, "type": "movie_scrape_task", "douban_id": "1292052", ...}
  1778308255.3  →  {"id": 46484014642499581, "type": "review_body_crawl", ...}
```

操作：

- `ZADD` — 加入延迟任务（add\_delayed\_task）
- `ZRANGEBYSCORE key -inf now LIMIT 0 N` + `ZREM` — 弹出到期任务（Lua 脚本原子操作，batch\_pop\_due\_tasks）

### 3.2 `crawler:last_task_time`（STRING）

```
Key:  crawler:last_task_time
类型: STRING
Value: 上一次任务的提交时间戳（float）

配合 Lua 脚本 LUA_ADD_WITH_RATE_LIMIT 使用：
  execute_at = max(now, last + cooldown)
  
默认 cooldown=2s，保证相邻任务至少间隔 2 秒进入队列。
未设置或过期时自动降级为 now + cooldown。
```

### 3.3 `crawler:rate_limit_events`（LIST）

```
Key:  crawler:rate_limit_events
类型: LIST
Value: JSON 字符串，含 timestamp / url / interval / retry_after

用于记录被限流的请求事件，供管理员查看 /admin/rate-limit-events。
默认保留最近 100 条，超出的头部弹出。
```

## 四、数据流一览

### 4.1 电影（解耦后架构）

```
榜单 API (豆瓣)
  → movie_crawl 任务
  → INSERT IGNORE douban_ids (is_acquired=0, is_scraped=0)
  → 首次执行时: INSERT IGNORE crawl_progress + 缓存 douban_total

管理员认领 → acquire → UPDATE is_acquired=1, admin_id=N

movie_scrape_task（单部详情爬取）
  → BrowserFetcher 爬详情页
  → parse_movie_detail(html)
  → save_movie_basic(movie_service, detail) — 原子事务:
      INSERT movies
      INSERT movie_genres + movie_genres_history
      INSERT regions（幂等）+ movie_regions + movie_regions_history
      INSERT movie_ratings
  → UPDATE douban_ids SET is_scraped=1
  → 自动 ZADD director_crawl 子任务（继承 admin_id）

director_crawl（演职人员补爬）
  → BrowserFetcher 爬 celebrities 页
  → parse_personnel(html)
  → save_crew(movie_service, movie_id, crew) — 原子事务:
      INSERT people（幂等）+ people_history
      INSERT movie_credits + movie_credits_history
  → task_history: submitted → running → done
```

### 4.2 长评

```
翻页 HTML (豆瓣)
  → review_crawl 任务
  → parse_review_list → INSERT IGNORE movie_review (status=pending)
  → 管理员查看 → review_body_crawl 任务
  → ApiFetcher /j/review/{id}/full API
  → parse_review_full → upsert MongoDB.reviews
  → UPDATE movie_review SET status='done'
```

### 4.3 短评

```
翻页 HTML (豆瓣)
  → comment_crawl 任务（一次到位，无需解耦）
  → parse_comments → upsert MongoDB.comments
  → task_history: submitted → running → done
```

## 五、分库依据

| 数据               |   存储位置  | 原因                     |
| ---------------- | :-----: | ---------------------- |
| 用户、权限、电影、演职人员、任务 |  MySQL  | 强关系，需要外键和事务            |
| 长评/短评            | MongoDB | 文档结构固定但量大，无需 JOIN      |
| 延迟队列、限速          |  Redis  | 高性能 ZSET 排序 + Lua 原子操作 |
