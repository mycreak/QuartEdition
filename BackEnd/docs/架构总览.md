## 二、多进程启动流程

```
hypercorn / uvicorn 主进程
  │
  ├─ create_app()                    ← 模块导入时执行
  │   ├─ Quart(__name__)
  │   ├─ CORS（开发 allow_origin="*"）
  │   ├─ before_request / after_request（访问日志 + 敏感字段脱敏）
  │   ├─ register_blueprint: /auth /user /admin /poster
  │   ├─ QuartSchema（OpenAPI 自动生成）
  │   └─ setup_json_logging()
  │
  ├─ before_serving:
  │   ├─ ① init_mysql() + init_redis() + init_mongodb()
  │   ├─ ② asyncio.Queue(maxsize=45)
  │   ├─ ③ init_snowflake(machine_id)
  │   ├─ ④ DatabaseLayerV2 + AppServices
  │   ├─ ⑤ init_puller → Puller 后台协程
  │   ├─ ⑥ init_tos_client
  │   ├─ ⑦ init_proxy_pool + 付费代理注入
  │   ├─ ⑧ init_cookie_manager（多账号加载）
  │   ├─ ⑨ Playwright start → chromium.launch(headless)
  │   ├─ ⑩ init_crawler(browser, movie_service, playwright, event_queue)
  │   ├─ ⑪ init_browser_pool(task_queue, crawler_execute, event_queue) → 5 Worker
  │   ├─ ⑫ init_ws_manager + register_websocket_routes
  │   ├─ ⑬ init_task_failure_service / task_history_service / review_service
  │   ├─ ⑭ init_auth_service
  │   └─ ⑮ init_monitor → Monitor 后台协程
  │
  ├─ while serving: 接收 HTTP 请求 + WebSocket
  │
  └─ after_serving（6 步优雅关闭）:
      ├─ ① stop_puller — 禁止新任务流入
      ├─ ② stop_browser_pool — 等待 in-flight（超时 30s）
      ├─ ③ drain 任务队列 — 剩余任务写回 Redis ZSET
      ├─ ④ stop_monitor
      ├─ ⑤ browser.close() → playwright.stop()
      └─ ⑥ asyncio.gather(close_mysql, close_redis, close_mongodb)
```

### 3.3 douban_ids 生命周期状态机

```

### 3.5 Redis Key

### 3.6 数据库连接器架构

```
DatabaseLayerV2（统一入口）
  ├─ ContextVar 隔离：每个 asyncio 任务持有独立的 DB 类型
  ├─ set_database("mysql" | "mongodb" | "redis")
  ├─ transaction() 上下文管理器（conn.begin → yield → commit/rollback）
  ├─ raw_mysql() → MySQLRawAccessV2（跳过 ORM，直接 SQL）
  ├─ raw_mongodb() → MongoDBRawAccessV2
  ├─ raw_redis() → RedisRawAccessV2
  └─ 安全防护：
       MySQL  — 参数化查询（aiomysql %s 占位符）
       MongoDB — 禁止 $where / $expr / 空查询删除
       Redis   — Lua 原子操作（batch_pop + add_with_limit）
```

## 四、爬虫引擎架构

### 4.1 任务流水线

```
管理员 POST /admin/tasks
  → Snowflake ID 生成
  → Redis ZSET ZADD（cooldown 2s 错开）
  → Puller 每 0.1s 批量弹出到期任务
  → asyncio.Queue(maxsize=45)
  → BrowserPool 5 Worker 抢任务
  → Worker jitter 2~5min（反爬错峰）
  → CrawlerEngine.execute(task_json)
       ├─ 解析 task.type → 分发到 _handle_xxx
       ├─ 构造 Identity（CookieManager + ProxyPool）
       ├─ Fetcher.fetch(url, identity) → HTML/JSON
       ├─ Parser.parse_xxx(raw) → dict/list
       ├─ Storage.save_xxx(service, data) → MySQL / MongoDB
       └─ 成功 → WorkerEvent(SUCCESS) → Monitor
          失败 → WorkerEvent(FAILURE) → Monitor → task_failures表 + WS推送
```

### 4.2 双引擎 Fetcher

| 引擎 | 工具 | 适用场景 | 单次耗时 | 反爬能力 |
|------|------|---------|:--:|------|
| `ApiFetcher` | aiohttp | JSON API + 非受限页面 | ~0.5s | UA 轮换 + 代理 + Cookie 注入 |
| `BrowserFetcher` | Playwright Chromium | 受 SHA-512 保护的 HTML | ~3.7s | 完整浏览器指纹 + networkidle + 挑战页自动完成 |

**双引擎共享能力**：
- ProxyPool 代理轮换（alive → 使用 → report_success/failure）
- IdentityManager Cookie+IP 绑定（约束检查）
- 崩溃自愈：BrowserFetcher 检测 `browser.is_connected()` 为 False → `_restart_browser()`（asyncio.Lock 防 5 Worker 同时重启）

### 4.3 8 种任务类型

| task.type | Fetcher | 处理函数 | 写入目标 | 数据流 |
|-----------|---------|---------|---------|--------|
| `movie_crawl` | ApiFetcher | `_handle_movie_crawl` | MySQL douban_ids → ZADD movie_scrape_task 子任务 | 榜单 API → INSERT IGNORE → 逐部派生子任务 |
| `movie_scrape_task` | BrowserFetcher | `_handle_movie_scrape_task` | MySQL movies/people/credits/genres/regions/ratings | 详情页 → parse_movie_detail → save_movie_basic → ZADD director_crawl |
| `movie_detail_crawl` | BrowserFetcher | `_handle_movie_detail_crawl` | MySQL（存量补爬，同上） | 旧版兼容路径 |
| `director_crawl` | BrowserFetcher | `_handle_director_crawl` | MySQL people + movie_credits | celebrities 页 → parse_personnel → save_crew |
| `review_crawl` | BrowserFetcher+ApiFetcher | `_handle_review_crawl` | MySQL movie_review（待爬表） | 长评列表 HTML → 逐条解析 → INSERT movie_review(status=pending) |
| `review_body_crawl` | ApiFetcher | `_handle_review_body_crawl` | MongoDB reviews | /j/review/{id}/full JSON → parse_review_full → save_reviews |

### 4.5 IdentityManager 约束链

```

### 4.6 Storage 写入顺序

两条路径，均在同一事务内原子执行，✨ 已不再写入 `*_history` 表（2026-05-21 移除）：

```
路径 A: _save_single_movie()  — movie_crawl 榜单采集（含演职人员）
  ① _mirror_poster(douban_url)                  → TOS（事务外，不阻塞）
  ② tx.insert("movies", {...})                  → movies
  ③ _find_or_create_person_in_tx(tx, name)      → people
     tx.insert("movie_credits", {movie_id, person_id, role_type})
                                                 → movie_credits
  ④ _resolve_type_num_in_tx(tx, genre_name)     → crawl_progress（只读）
     tx.insert("movie_genres", ...)              → movie_genres
  ⑤ _find_or_create_region_in_tx(tx, name)      → regions
     tx.insert("movie_regions", ...)             → movie_regions
  ⑥ tx.insert("movie_ratings", ...)             → movie_ratings（幂等）

路径 B: save_movie_basic()    — movie_scrape_task 详情页采集（不含演职人员）
  ① _mirror_poster(douban_url)                  → TOS（事务外）
  ② tx.insert("movies", {...})                  → movies
  ③ _resolve_type_num_in_tx → tx.insert("movie_genres", ...)
                                                 → movie_genres
  ④ _find_or_create_region_in_tx → tx.insert("movie_regions", ...)
                                                 → movie_regions
  ⑤ tx.execute_raw("INSERT INTO movie_ratings...")
                                                 → movie_ratings
```

> ⚠️ 与旧版差异：`storage.py` 不再调用 `MovieService.create_movie()` / `add_credit()` / `add_genre_to_movie()` 等包装方法，而是直接通过 `tx.insert()` 写入，避免 history 副作用。演职人员由 `save_crew()` 在事务外独立写入。

## 五、后台调度系统

### 5.1 三层协同架构

```
┌──────────────────────────────────────────────────────────────────┐
│  Redis ZSET (crawler:delay_queue)                                │
│  Score=execute_at(浮点秒)  Member=task JSON                       │
└──────────────┬───────────────────────────────────────────────────┘
               │ 批量弹出到期任务 (Lua 原子: ZRANGEBYSCORE + ZREM)
┌──────────────▼───────────────────────────────────────────────────┐
│  Puller（单协程）                                                  │
│  每 0.1s 检查 ZSET → batch_pop_due_tasks(now, batch_size=10)      │
│  → asyncio.Queue(maxsize=45)                                      │
│  背压控制：queue 饱和度 > 0.8 → 暂停拉取 → 降至 0.6 恢复           │
│  空轮询：指数退避 0.1s→0.2s→0.4s→…→max 5.0s                       │
└──────────────┬───────────────────────────────────────────────────┘
               │
┌──────────────▼───────────────────────────────────────────────────┐
│  BrowserPool（5 Worker 协程，固定容量）                            │
│  每个 Worker:                                                      │
│    await task_queue.get()                                         │
│    → jitter = random(120s, 300s) → asyncio.sleep(jitter)          │
│    → execute_func(task) → 成功: WorkerEvent(SUCCESS)               │
│                         → 失败: WorkerEvent(FAILURE, kind=…)       │
│    → event_queue.put(event)                                       │
│  崩溃自愈: restart_dead_workers() 检测已取消的 Task → 重新建协程     │
└──────────────┬───────────────────────────────────────────────────┘
               │ 消费事件队列
┌──────────────▼───────────────────────────────────────────────────┐
│  Monitor（单协程，每 10s 一轮）                                    │
│  ① 采集 Puller 指标（state, fetched, empty_polls, backpressure）  │
│  ② 采集队列指标（queue_size, saturation）                          │
│  ③ 采集 BrowserPool 指标（alive/busy/dead/stuck/crashed）         │
│  ④ 消费 Worker 事件队列（成功计数 / 失败写入 task_failures）        │
│  ⑤ 采集系统资源（CPU/内存 psutil）                                  │
│  ⑥ 数据库健康检查（MySQL/Redis/MongoDB ping）                      │
│  ⑦ 输出报告日志 + WS system_status 广播（1s 节流）                 │
│  ⑧ 崩溃自愈：检测 dead Worker → 自动重启 + WS worker_crash 广播    │
└──────────────────────────────────────────────────────────────────┘
```

### 5.2 Puller 状态机与参数

```
PullerState: INITIALIZED → RUNNING ↔ BACKPRESSURE → STOPPED

配置（PullerConfig, 环境变量前缀 PULLER_）:
  backpressure_high: 0.8        队列饱和度进入背压水位线
  backpressure_low:  0.6        退出背压水位线
  base_sleep:        0.1s       无任务初始休眠
  max_sleep:         5.0s       指数退避上限
  backpressure_sleep: 0.5s      背压态固定休眠
  batch_size:        10         单次批量弹出数
  task_cooldown_seconds: 2.0s   相邻任务最小间隔（ZSET score 错开）
  worker_rest_min:   150s       Worker 执行后最少休息
  worker_rest_max:   250s       Worker 执行后最多休息
```

### 5.3 Worker 反爬错峰

```
5 个 Worker 各自独立:
  Worker 0: 取任务 → jitter=137s → 执行(~25s) → rest~180s → 取下一个
  Worker 1: 取任务 → jitter=284s → 执行(~25s) → rest~220s → 取下一个
  ...自然错峰，豆瓣视角始终是单线程低频访问
```

### 5.4 失败事件处理链路

```
Worker 捕获异常
  → classify_exception(exc) → FailureKind(NETWORK/TIMEOUT/HTTP/PARSE/STORAGE/ABUSE/…)
  → WorkerEvent(type=FAILURE, kind=…, worker_id, task, reason, timestamp)
  → event_queue.put(event.model_dump())
  ↓
Monitor._drain_events()
  → WorkerEvent.model_validate(raw)
  → _write_failure_event(event)
      → INSERT INTO task_failures（17 列，scope=batch/item，含 failure_layer）
      → ws_manager.push(admin_id, {type:"task_failure", …})  → 前端弹窗
```

## 八、用户行为评分子系统

> 4 张 MySQL 表 + 5 种操作 + 状态机递进 + 时间衰减算法 + 标签画像

### 8.1 整体数据流

```
用户 POST/DELETE /user/movies/<id>/<action>
  │
  ▼
UserActionService.execute_action(user_id, movie_id, action, review_text?, rating?)
  │
  ├─ ① 状态校验
  │     ┌ 幂等：已标记过 → 拒绝
  │     └ 递进：想看→在看→看过，标记看过时自动回滚前两级积分
  │
  ├─ ② MovieContextService.build(movie_id)
  │     从 movies/people/credits/genres/regions/movie_style/review_summary
  │     拼装归一化标签 [{dimension, label, confidence, weight, source}, ...]
  │
  ├─ ③ 计算分数
  │     每个标签: delta = 操作权重 × 维度权重 × 位置衰减 × confidence
  │     评论操作: effective_weight = 操作权重 × rating_factor(评分)   ← v1.1
  │     total_score = Σ delta
  │
  └─ ④ MySQL 事务写入
       tx: user_movie_status(UPSERT) + user_action_log(INSERT) + user_tag_score(UPSERT×N)
       递进回滚: user_action_log(INSERT负分) + user_tag_score(抵扣)
       评论: 额外写 MongoDB comments（幂等 upsert），delta 可为负数（差评扣分）
  │
  ▼
返回 ActionResult { action, movie_id, score_total, tag_count }
```

### 8.2 5 种操作类型及权重

| 操作 | 权重 | 约束 | 说明 |
|------|:---:|------|------|
| `want_watch` (想看) | 1.0 | 幂等 | 标记想看的电影 |
| `watching` (在看) | 1.2 | 必须先想看 | 递进：自动回滚 want_watch 积分 |
| `watched` (看过) | 2.0 | 必须先在看或看过 | 递进：自动回滚 watching 积分 |
| `favorite` (收藏) | 1.5 | 独立操作 | 与观看状态无关 |
| `comment` (评论) | 3.0 | 必须先看过 | 额外写入 MongoDB，幂等；**v1.1** 评分＞3加分、＜3扣分 |

> 权重通过 `config_score_weight` 表 `action.*` 行热加载，`UserActionService._ensure_config()` 懒加载到内存

### 8.3 观看状态机

```
      POST want_watch        POST watching         POST watched
NULL ─────────────────→ 想看 ────────────→ 在看 ────────────→ 看过
  ▲         │               ▲      │              ▲      │
  │    DELETE want_watch     │ DELETE watching     │ DELETE watched
  └──────────────────────────┴────────────────────┘
                             积分回滚: 标记观看时自动插入上一级的负分记录
```

递进回滚细节：
- 标记 `watching` 时：自动查找活跃的 `want_watch` 记录 → 插入 `want_watch` 负分 + 标记 `reverted_at`
- 标记 `watched` 时：同上回滚 `watching`，且已有 `want_watch` 的活跃记录一并回滚

### 8.4 标签分数计算

```
单个标签 delta = effective_weight × 维度权重(dim.*) × 位置衰减(actor.decay.N) × confidence

effective_weight = action_weight(action.*) × rating_factor(rating)  ← comment（v1.1）
                   action_weight(action.*)                            ← 其他操作

评分调节因子（comment 专用，v1.1）：
  rating_factor = factor_max × (rating - neutral) / (5.0 - neutral)    当 rating ≥ neutral
  rating_factor = factor_min × (neutral - rating) / (neutral - 1.0)    当 rating < neutral
  默认配置: neutral=3.0  factor_max=1.0  factor_min=-0.5
  5星→+3.0  4星→+1.5  3星→0  2星→-0.75  1星→-1.50

维度权重（默认值）：
  era:0.3  region:0.4  director:1.0  actor:0.8  genre:0.6
  overall:0.7  plot:0.7  visual:0.7  narrative:0.7  pacing:0.7

演员位置衰减（前5名）：
  第1名:1.0  第2名:0.85  第3名:0.70  第4名:0.55  第5名:0.40

标签来源（source）：
  douban — 年代/地区/导演/演员/类型，confidence 固定 1.0
  ai     — 5维度风格标签（来自 review_summary），confidence 0.5~0.9
```

### 8.5 时间衰减（标签画像查询）

查询 `GET /user/profile/tags?decayed=true` 时触发：

```
衰减窗口：
  30天内      × 1.0
  30~90天     × 0.8
  90~180天    × 0.5
  180天以上    × 0.2

算法：
  ① 查 user_action_log 中所有未回滚且含 tag_deltas_json 的记录
  ② 每条记录的 tag_deltas_json 中的 delta × 对应的窗口衰减系数
  ③ 按 (dimension, label) 聚合 → 输出用户当前有效画像
```

> `GET /user/profile/tags/<dimension>` 支持按维度（如 `director`、`genre`）单独查询

### 8.6 回滚（DELETE 操作）

```
DELETE /user/movies/<id>/watched
  → 查原始操作记录（tag_deltas_json + score_delta）
  → 事务:
      ① user_movie_status 恢复标记位
      ② 标记原记录 reverted_at=NOW()
      ③ 插入负分回滚记录（score_delta = -原值）
      ④ 逐标签抵扣 user_tag_score（delta = -原值）
  → 返回 ActionResult(score_total 为负值)
```

### 8.7 评论写 MongoDB

`POST /user/movies/<id>/comment` 通过 `UserActionService._write_review_to_mongo()`：

```
MongoDB 文档 _id = "user_{user_id}_movie_{movie_id}"
  { movie_id, movie_douban_id, user_id, author(脱敏), rating, text, date, is_published, crawled_at }

幂等 upsert: 重复评论覆盖旧内容，不创建新文档
昵称脱敏: _mask_author("张三丰") → "张三**"
```

## 九、推荐引擎

> 基于用户标签画像 + 变异系数(CV)自适应推荐 · 精准/探索双模式 · 冷启动兜底

### 9.1 算法总流程

```
GET /user/recommend?top_n=10
  │
  ▼
RecommendService.recommend(user_id, top_n)
  │
  ├─ ① 拿用户画像（衰减版） → UserActionService.get_user_tag_profile(decayed=True)
  │     无画像 → 冷启动兜底（按评分降序返回热门）
  │
  ├─ ② 计算各维度变异系数 CV = σ / μ
  │     CV > recommend.cv_threshold(默认0.5) → 精准模式
  │     CV ≤ 0.5 或 μ < 0.01                   → 探索模式
  │
  ├─ ③ 获取候选池（已上架 + 排除该用户 watched 的电影，上限 200）
  │
  ├─ ④ 批量加载候选电影标签 → MovieContextService.build(movie_id)
  │
  ├─ ⑤ 逐电影打分
  │     ┌ 精准: Σ user_tag_score[label] × confidence
  │     └ 探索: Σ random(0,1) × dim_weight
  │
  ├─ ⑥ 按分降序 → 取 top_n
  │
  └─ ⑦ 补全评分 → 响应 [{movie_id, douban_id, title, poster_url, release_year, score, rating}, ...]
```

### 9.2 变异系数（CV）自适应分流

```
CV = σ / μ（标准差 / 均值）

10 个维度各自独立计算 CV：
  douban 维度: era, region, director, actor, genre
  AI 维度:    overall, plot, visual, narrative, pacing

维度内 0 或 1 个标签 → CV = 0 → 强制探索
维度内 μ < 0.01       → CV = 0 → 强制探索（分数太低无区分度）

cv_threshold 默认 0.5，通过 config_score_weight 表 recommend.cv_threshold 热加载

典型场景：
  - 新用户（全部维度 CV=0）→ 全探索 → 随机发现
  - 老影迷（导演 CV=1.2，类型 CV=0.3）
    → 导演走精准匹配，类型走探索
```

### 9.3 精准模式 vs 探索模式

| 模式 | 触发条件 | 打分公式 | 效果 |
|------|---------|---------|------|
| **精准** | CV > threshold | `Σ user_score[label] × confidence` | 匹配用户偏好导演/演员/风格 |
| **探索** | CV ≤ threshold | `Σ random(0,1) × dim_weight` | 随机加权，引导发现新内容 |

```
示例：用户导演维度 CV=1.2 > 0.5 → 精准
  候选电影标签: [{dim:"director", label:"吕克·贝松", confidence:1.0}]
  用户对 "吕克·贝松" 标签分数: 8.5
  → 导演维度得分: 8.5 × 1.0 = 8.5

示例：用户年代维度 CV=0.2 ≤ 0.5 → 探索
  候选电影标签: [{dim:"era", label:"1990s年代", confidence:1.0}]
  → 年代维度得分: random(0,1) × 0.3 = 0.07
```

> 每部电影的最终分数 = 所有维度得分之和，每轮 random 不同 → 探索结果天然带多样性

### 9.4 冷启动

```
user_tag_score 表无该用户记录
  ↓
SELECT movies + movie_ratings
  WHERE is_published=1
  ORDER BY mr.average DESC
  LIMIT 50
  ↓
返回评分最高的热门电影（不含用户行为加权）
```

### 9.5 候选池

```
SELECT DISTINCT m.id FROM movies m
  WHERE is_published = 1
    AND m.id NOT IN (
      SELECT movie_id FROM user_action_log
      WHERE user_id = %s AND action='watched' AND reverted_at IS NULL
    )
  ORDER BY m.id DESC
  LIMIT 200
```

- 排除用户已「看过」的电影（不含回滚的）
- 上限 200 部（性能保护，MovieContextService.build 每部 6 次查询）
- 按 id DESC → 优先推荐新入库电影

### 9.6 相关 API & 依赖

| 端点 | 说明 |
|------|------|
| `GET /user/recommend?top_n=10` | 个性化推荐（max 50） |

依赖：
- `UserActionService` — 拿衰减版用户画像
- `MovieContextService` — 批量构建电影标签上下文
- `config_score_weight` — `recommend.cv_threshold` + `dim.*` 权重 + `comment.rating_*` 评分调节（v1.1）

## 十一、风格标签管理

> AI 从评论中自动提取风格标签 · 5 维度 · 相似度检测 · 管理员审核合并

### 11.1 标签生命周期

```
AI 生成总结 → 每部电影提取 5 个标签（5 维度各一）
  ↓
INSERT INTO movie_style_tag (name, dimension, review_status=0)   ← 新标签，未检测
  ↓
INSERT INTO movie_style (movie_id, tag_id, confidence)           ← 关联电影
  ↓
_trigger_similarity_check(tag_id, dimension)                     ← fire-and-forget
  │
  ├─ 同维度无已有标签 → status=1（自动确认，无需审核）
  │
  ├─ AI 对比最高相似度 < 82% → status=1（自动确认）
  │
  └─ AI 对比最高相似度 ≥ 82% → status=2（待审核），记录 merged_to_tag_id
       ↓
     管理员审核:
       ├─ 确认合并 → status=3（事务: 迁移 movie_style 关联 → 删除旧关联 → 改状态）
       └─ 拒绝合并 → status=1（改状态，不迁移数据）
```

### 11.2 5 维度

| 维度 | 中文含义 | 示例标签 |
|------|---------|---------|
| `overall` | 整体风格 | 黑暗压抑、轻松治愈、史诗感、荒诞、浪漫 |
| `plot` | 剧情风格 | 反转密集、非线性叙事、真实事件改编、多线交织 |
| `visual` | 画面风格 | 冷色调、手持摄影、长镜头、色彩饱和、极简构图 |
| `narrative` | 叙事风格 | 第一人称、倒叙、多视角、留白、碎片化 |
| `pacing` | 节奏风格 | 前松后紧、全程紧绷、缓慢铺陈、循序渐进 |

> 唯一键约束：`(name, dimension)` 联合唯一，同维度同名标签只存一行

### 11.3 4 态状态机

```
status 状态:
  0 = 新标签，未检测
  1 = 已检测，无需合并（自动确认 或 管理员拒绝合并后）
  2 = 待审核（AI 判定相似度 ≥ 82%）
  3 = 已合并（管理员确认 → 关联迁移完成）
```

### 11.4 AI 相似度检测

```
StyleTagService.check_similarity(tag_id, dimension)
  │
  ├─ ① 校验 status=0（非 0 抛 TagAlreadyProcessedError）
  │
  ├─ ② 查同维度已有标签（status IN (0, 1)）
  │     空 → status=1，返回
  │
  ├─ ③ 遍历已有标签，逐对调用 AI
  │     DeepSeekAIClient.compare_style_tags(tag_a, tag_b, dimension, movie_a, movie_b)
  │     → 返回 0~100 相似度
  │     附带来电影名作为上下文（提升 AI 判断准确度）
  │
  └─ ④ 取最高分判定
        ≥ 82% → status=2, merged_to_tag_id=最高分标签
        < 82% → status=1
```

### 11.5 管理员审核

**确认合并** (`POST /admin/style-tags/pending/<id>/confirm-merge`)：

```
事务内执行:
  ① 查待合并标签 → 取 merged_to_tag_id
  ② 将所有引用待合并标签的 movie_style 行
     改为引用 merged_to_tag_id（已存在则更新 confidence 取两者较大值）
  ③ DELETE 被合并标签的 movie_style 行（已迁移完毕的残留）
  ④ UPDATE movie_style_tag SET review_status=3
```

**拒绝合并** (`POST /admin/style-tags/pending/<id>/reject`)：

```
UPDATE movie_style_tag SET review_status=1, merged_to_tag_id=NULL
```

## 十四、认证鉴权全链路

### 14.1 认证流程

```
┌─────────────────────────────────────────────────────────────────┐
│ ① 登录                                                          │
│                                                                  │
│  POST /auth/login { username, password }                        │
│    ├─ 限流检查：同一 IP 60s 内最多 5 次（Redis 滑动窗口 + Lua）   │
│    ├─ AuthService.authenticate()                                │
│    │   ├─ get_user_by_username() → 查 users 表                   │
│    │   ├─ bcrypt.checkpw(password, password_hash) → 密码校验     │
│    │   └─ is_active 检查 → 禁用则抛 UserDisabledError            │
│    ├─ AuthService.create_token(user_id)                         │
│    │   └─ jwt.encode({ sub, iat, exp }, JWT_SECRET, HS256)      │
│    ├─ AuthService.get_user_permissions(user_id)                  │
│    └─ 返回 { token, user: { id, uuid, username, avatar_url, permissions } } │
│                                                                  │
│ ② 后续请求                                                       │
│                                                                  │
│  每个 HTTP 请求 → Authorization: Bearer <JWT>                    │
│    ├─ get_current_user()                                        │
│    │   ├─ 提取 header["Authorization"][7:]                       │
│    │   ├─ AuthService.verify_token(token)                        │
│    │   │   └─ jwt.decode(token, JWT_SECRET) → user_id            │
│    │   │   └─ ExpiredSignatureError → None                       │
│    │   ├─ AuthService.get_user(user_id) → 查 users 表             │
│    │   └─ 检查 is_active → True=返回 user_id / False=返回 0       │
│    └─ g.user_id = user_id（Quart ContextVar 请求级隔离）         │
│                                                                  │
│ ③ 权限校验                                                       │
│                                                                  │
│  @require_permission("movie:manage")                             │
│    ├─ get_current_user() → user_id（0=未登录）                    │
│    ├─ 0 → 401 { "error": "未登录或登录已过期" }                   │
│    ├─ AuthService.check_permission(user_id, code)                │
│    │   └─ SELECT 1 FROM user_permissions WHERE …                 │
│    ├─ False → 403 { "error": "无权限: movie:manage" }            │
│    └─ True → g.user_id = user_id → 执行 handler                  │
│                                                                  │
│  @require_login                                                  │
│    └─ 同上但不查权限表，仅校验登录状态                              │
└─────────────────────────────────────────────────────────────────┘
```

### 14.2 密码安全

```
注册 / 管理员创建用户:
  password (明文) → bcrypt.hashpw(password, gensalt(rounds=12)) → password_hash
  → INSERT INTO users (password_hash)

登录:
  password (明文) → bcrypt.checkpw(password, password_hash) → True/False

JWT:
  palyload: { sub: str(user_id), iat: 当前时间(CST), exp: iat + 7天 }
  算法: HS256
  密钥: settings.JWT_SECRET（必须通过 .env 显式设置，默认为空=启动拒绝）
```

### 14.4 权限表设计（3 表）

```
users ──1:N── user_permissions ──N:1── permissions
  id              user_id                code (PK)
  uuid            permission_code        name
  username        granted_by             description
  password_hash   granted_at
  avatar_url
  display_name
  is_active

权限分配流程:
  POST /admin/users/<id>/permissions { permission_codes: [...] }
    → AuthService.set_permissions(data)
      → BEGIN TRANSACTION
      → DELETE FROM user_permissions WHERE user_id = ?
      → INSERT INTO user_permissions (user_id, permission_code, granted_by) × N
      → COMMIT
```

### 14.5 统一异常体系

```
ServiceError (基类)
  ├─ BadRequestError (400)
  ├─ UnauthorizedError (401)
  │   ├─ AuthenticationError — 用户名或密码错误
  │   └─ UserDisabledError — 账户已被禁用 (code=USER_DISABLED)
  ├─ ForbiddenError (403)
  ├─ NotFoundError (404) — 资源不存在: {resource} {identifier}
  ├─ ConflictError (409)
  │   └─ DuplicateError — 资源已存在 (code=DUPLICATE)
  └─ TooManyRequestsError (429) — 请求频率超限

路由层统一处理:
  try:
      result = await service.method(...)
  except ServiceError as e:
      return jsonify({"error": e.message, "code": e.code}), e.status_code
```
