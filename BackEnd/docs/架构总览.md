## 二、多进程启动流程

```
hypercorn / uvicorn 主进程
  │
  ├─ create_app()                    ← 模块导入时执行
  │   ├─ Quart(__name__)
  │   ├─ CORS（开发 allow_origin="*"）
  │   ├─ before_request / after_request（访问日志 + 敏感字段脱敏）
  │   ├─ register_blueprint: /auth /user /admin /poster
  │   ├─ QuartSchema（OpenAPI 自动生成）
  │   └─ setup_json_logging()
  │
  ├─ before_serving:
  │   ├─ ① init_mysql() + init_redis() + init_mongodb()
  │   ├─ ② asyncio.Queue(maxsize=45)
  │   ├─ ③ init_snowflake(machine_id)
  │   ├─ ④ DatabaseLayerV2 + AppServices
  │   ├─ ⑤ init_puller → Puller 后台协程
  │   ├─ ⑥ init_tos_client
  │   ├─ ⑦ init_proxy_pool + 付费代理注入
  │   ├─ ⑧ init_cookie_manager（多账号加载）
  │   ├─ ⑨ Playwright start → chromium.launch(headless)
  │   ├─ ⑩ init_crawler(browser, movie_service, playwright, event_queue)
  │   ├─ ⑪ init_browser_pool(task_queue, crawler_execute, event_queue) → 5 Worker
  │   ├─ ⑫ init_ws_manager + register_websocket_routes
  │   ├─ ⑬ init_task_failure_service / task_history_service / review_service
  │   ├─ ⑭ init_auth_service
  │   └─ ⑮ init_monitor → Monitor 后台协程
  │
  ├─ while serving: 接收 HTTP 请求 + WebSocket
  │
  └─ after_serving（6 步优雅关闭）:
      ├─ ① stop_puller — 禁止新任务流入
      ├─ ② stop_browser_pool — 等待 in-flight（超时 30s）
      ├─ ③ drain 任务队列 — 剩余任务写回 Redis ZSET
      ├─ ④ stop_monitor
      ├─ ⑤ browser.close() → playwright.stop()
      └─ ⑥ asyncio.gather(close_mysql, close_redis, close_mongodb)
```

## 三、数据库设计

### 3.1 三库全景

| 数据库 | 版本 | 存储内容 |
|--------|------|---------|
| **MySQL** | 8.0 / Docker | 21 张表 — 用户/权限/电影/人员/评分/任务/历史 |
| **MongoDB** | 6.0+ | 2 个集合 — `reviews`(长评) / `comments`(短评) |
| **Redis** | 7.0 | 3 种 Key — ZSET 延迟队列 / 限流 / 词云缓存 |

### 3.2 MySQL 表定义（21 表）

#### 核心业务表（9 张）

| 表 | 主键 | 说明 |
|------|------|------|
| `movies` | INT AUTO_INCREMENT | 电影基本信息（douban_id UNIQUE, poster_url, is_published） |
| `people` | INT AUTO_INCREMENT | 人员（name UNIQUE, douban_id UNIQUE） |
| `regions` | INT AUTO_INCREMENT | 地区字典（name UNIQUE） |
| `movie_credits` | (movie_id, person_id, role_type) PK | 演职人员关联（role_type: director/actor/writer…） |
| `movie_genres` | (movie_id, type_num) PK | 类型关联（type_num 逻辑引用 crawl_progress） |
| `movie_regions` | (movie_id, region_id) PK | 地区关联 |
| `movie_ratings` | movie_id (PK) | 评分（average DECIMAL 3,1 + count + distribution JSON） |
| `douban_ids` | douban_id (PK) | 豆瓣电影 ID 资产（is_acquired + is_scraped 双状态机） |
| `crawl_progress` | INT AUTO_INCREMENT | 爬取进度 + 类型字典（双重角色） |

#### 用户与权限表（3 张）

| 表 | 主键 | 说明 |
|------|------|------|
| `users` | INT AUTO_INCREMENT | 用户（uuid snowflake, password_hash bcrypt, avatar_url, display_name, is_active） |
| `permissions` | code (PK) VARCHAR(32) | 权限字典（14 条: user:manage / crawler:task:read/write / …） |
| `user_permissions` | (user_id, permission_code) PK | 用户权限关联（FK CASCADE） |

#### 任务与日志表（4 张）

| 表 | 主键 | 说明 |
|------|------|------|
| `task_history` | BIGINT (snowflake) PK | 任务历史（task_type/task_category/task_params JSON/parent_task_id/status/message/elapsed_ms） |
| `task_failures` | INT AUTO_INCREMENT | 失败任务（18 列: kind/failure_layer/status/scope/parent_failure_id…） |
| `movie_review` | review_id (PK) | 长评待爬表（status: pending/done/failed） |

#### 版本历史表（5 张）

| 表 | 说明 |
|------|------|
| `movies_history` | 电影变更历史（change_type + changed_by + 全量快照） |
| `people_history` | 人员变更历史 |
| `movie_credits_history` | 演职人员变更历史 |
| `movie_regions_history` | 地区关联变更历史 |
| `movie_genres_history` | 类型关联变更历史 |

### 3.3 douban_ids 生命周期状态机

```
is_scraped=0, is_acquired=0 → 未认领（movie_crawl 写入）
is_scraped=0, is_acquired=1 → 已认领，排队爬取中
is_scraped=1, is_acquired=1 → 终态：已爬取完成（不可释放/重认领）
```

### 3.4 MongoDB 集合

| 集合 | 文档结构 | 说明 |
|------|---------|------|
| `reviews` | `{ movie_id, douban_subject_id, author, rating, content, likes, is_published, crawled_at }` | 长评 |
| `comments` | `{ movie_id, author, rating, text, useful_count, is_published, crawled_at }` | 短评 |

### 3.5 Redis Key

| Key | 类型 | 用途 |
|-----|------|------|
| `crawler:delay_queue` | ZSET | 延迟任务队列（score=execute_at, member=task JSON） |
| `crawler:dedup:review_body:{id}` | String | review_body_crawl 去重标记（TTL 3600s） |
| `ratelimit:login:{ip}` | String | 登录限流（60s 窗口，5 次） |
| `ratelimit:register:{ip}` | String | 注册限流（60s 窗口，3 次） |
| `wordcloud:movie:{id}` | String | 词云缓存（永久 + 主动失效） |

### 3.6 数据库连接器架构

```
DatabaseLayerV2（统一入口）
  ├─ ContextVar 隔离：每个 asyncio 任务持有独立的 DB 类型
  ├─ set_database("mysql" | "mongodb" | "redis")
  ├─ transaction() 上下文管理器（conn.begin → yield → commit/rollback）
  ├─ raw_mysql() → MySQLRawAccessV2（跳过 ORM，直接 SQL）
  ├─ raw_mongodb() → MongoDBRawAccessV2
  ├─ raw_redis() → RedisRawAccessV2
  └─ 安全防护：
       MySQL  — 参数化查询（aiomysql %s 占位符）
       MongoDB — 禁止 $where / $expr / 空查询删除
       Redis   — Lua 原子操作（batch_pop + add_with_limit）
```

## 四、爬虫引擎架构

### 4.1 任务流水线

```
管理员 POST /admin/tasks
  → Snowflake ID 生成
  → Redis ZSET ZADD（cooldown 2s 错开）
  → Puller 每 0.1s 批量弹出到期任务
  → asyncio.Queue(maxsize=45)
  → BrowserPool 5 Worker 抢任务
  → Worker jitter 2~5min（反爬错峰）
  → CrawlerEngine.execute(task_json)
       ├─ 解析 task.type → 分发到 _handle_xxx
       ├─ 构造 Identity（CookieManager + ProxyPool）
       ├─ Fetcher.fetch(url, identity) → HTML/JSON
       ├─ Parser.parse_xxx(raw) → dict/list
       ├─ Storage.save_xxx(service, data) → MySQL / MongoDB
       └─ 成功 → WorkerEvent(SUCCESS) → Monitor
          失败 → WorkerEvent(FAILURE) → Monitor → task_failures表 + WS推送
```

### 4.2 双引擎 Fetcher

| 引擎 | 工具 | 适用场景 | 单次耗时 | 反爬能力 |
|------|------|---------|:--:|------|
| `ApiFetcher` | aiohttp | JSON API + 非受限页面 | ~0.5s | UA 轮换 + 代理 + Cookie 注入 |
| `BrowserFetcher` | Playwright Chromium | 受 SHA-512 保护的 HTML | ~3.7s | 完整浏览器指纹 + networkidle + 挑战页自动完成 |

**双引擎共享能力**：
- ProxyPool 代理轮换（alive → 使用 → report_success/failure）
- IdentityManager Cookie+IP 绑定（约束检查）
- 崩溃自愈：BrowserFetcher 检测 `browser.is_connected()` 为 False → `_restart_browser()`（asyncio.Lock 防 5 Worker 同时重启）

### 4.3 8 种任务类型

| task.type | Fetcher | 处理函数 | 写入目标 | 数据流 |
|-----------|---------|---------|---------|--------|
| `movie_crawl` | ApiFetcher | `_handle_movie_crawl` | MySQL douban_ids → ZADD movie_scrape_task 子任务 | 榜单 API → INSERT IGNORE → 逐部派生子任务 |
| `movie_scrape_task` | BrowserFetcher | `_handle_movie_scrape_task` | MySQL movies/people/credits/genres/regions/ratings | 详情页 → parse_movie_detail → save_movie_basic → ZADD director_crawl |
| `movie_detail_crawl` | BrowserFetcher | `_handle_movie_detail_crawl` | MySQL（存量补爬，同上） | 旧版兼容路径 |
| `director_crawl` | BrowserFetcher | `_handle_director_crawl` | MySQL people + movie_credits | celebrities 页 → parse_personnel → save_crew |
| `review_crawl` | BrowserFetcher+ApiFetcher | `_handle_review_crawl` | MySQL movie_review（待爬表） | 长评列表 HTML → 逐条解析 → INSERT movie_review(status=pending) |
| `review_body_crawl` | ApiFetcher | `_handle_review_body_crawl` | MongoDB reviews | /j/review/{id}/full JSON → parse_review_full → save_reviews |
| `comment_crawl` | BrowserFetcher | `_handle_comment_crawl` | MongoDB comments | 短评列表 HTML → parse_comments → save_comments |
| `ai_review_summary` | ApiFetcher+DeepSeek | `_handle_ai_review_summary` | MySQL movies（ai_summary/ai_tags） | 取该电影所有已上架长评 → DeepSeek → 更新电影行 |

### 4.4 反爬五层防线

```
┌─────────────────────────────────────────────────────────────────┐
│ 第1层 — User-Agent 池（5 种 Chrome/Firefox UA 随机轮换）        │
│                                                                  │
│ 第2层 — 请求节流                                                │
│   ZSET cooldown 2s（入库层面） + Worker jitter 2~5min（执行层面） │
│   BROWSER_SEMAPHORE=2: 同时最多 2 个 Playwright 页面             │
│                                                                  │
│ 第3层 — IP 代理池                                               │
│   ProxyPool 状态机: UNKNOWN→ALIVE↔SUSPICIOUS→BANNED            │
│   来源: 管理员手动添加 + 付费代理 (.env PAID_PROXIES)，TTL 7 天 |
│   管理端 7 个 CRUD + 验证 API                                    │
│                                                                  │
│ 第4层 — Cookie + IP 显式绑定                                     │
│   IdentityManager: cookie_id + proxy_key 组合                   │
│   CookieManager: active↔suspicious→banned 状态机（多账号）      │
│   约束：Cookie.allowed_regions 匹配 Proxy.region                 │
│                                                                  │
│ 第5层 — 挑战页处理                                              │
│   SHA-512: wait_for_timeout(3000) 自动完成                       │
│   "检测到有异常请求" → 触发代理重试                              │
└─────────────────────────────────────────────────────────────────┘
```

### 4.5 IdentityManager 约束链

```
管理员提交任务 → 选择 cookie_id + proxy_key
  ↓
IdentityManager.resolve(cookie_id, proxy_key)
  ├─ ① 从 CookieManager 获取 Account → 读取 storage_state
  ├─ ② 从 ProxyPool 获取 Proxy → 构造 proxy_config
  ├─ ③ 检查: account.allowed_regions 是否包含 proxy.region
  └─ ④ 返回 Identity(frozen=True, 不可变)
  ↓
BrowserFetcher.fetch(url, identity)
  └─ 使用 identity.storage_state + identity.proxy_config 发起请求
```

### 4.6 Storage 写入顺序

```
save_movie_basic() → 单部电影原子事务:
  1. create_movie(douban_id, title, …)           → movies
  2. _find_or_create_person(name, douban_id)      → people
  3. add_credit(movie_id, person_id, role_type)   → movie_credits
  4. _resolve_type_num(type_name)                 → crawl_progress（只查不建）
  5. add_genre_to_movie(movie_id, type_num)       → movie_genres
  6. _find_or_create_region(name)                 → regions
  7. add_region_to_movie(movie_id, region_id)     → movie_regions
  8. set_rating(score, vote_count)                → movie_ratings（幂等 INSERT ON DUPLICATE）
```

## 五、后台调度系统

### 5.1 三层协同架构

```
┌──────────────────────────────────────────────────────────────────┐
│  Redis ZSET (crawler:delay_queue)                                │
│  Score=execute_at(浮点秒)  Member=task JSON                       │
└──────────────┬───────────────────────────────────────────────────┘
               │ 批量弹出到期任务 (Lua 原子: ZRANGEBYSCORE + ZREM)
┌──────────────▼───────────────────────────────────────────────────┐
│  Puller（单协程）                                                  │
│  每 0.1s 检查 ZSET → batch_pop_due_tasks(now, batch_size=10)      │
│  → asyncio.Queue(maxsize=45)                                      │
│  背压控制：queue 饱和度 > 0.8 → 暂停拉取 → 降至 0.6 恢复           │
│  空轮询：指数退避 0.1s→0.2s→0.4s→…→max 5.0s                       │
└──────────────┬───────────────────────────────────────────────────┘
               │
┌──────────────▼───────────────────────────────────────────────────┐
│  BrowserPool（5 Worker 协程，固定容量）                            │
│  每个 Worker:                                                      │
│    await task_queue.get()                                         │
│    → jitter = random(120s, 300s) → asyncio.sleep(jitter)          │
│    → execute_func(task) → 成功: WorkerEvent(SUCCESS)               │
│                         → 失败: WorkerEvent(FAILURE, kind=…)       │
│    → event_queue.put(event)                                       │
│  崩溃自愈: restart_dead_workers() 检测已取消的 Task → 重新建协程     │
└──────────────┬───────────────────────────────────────────────────┘
               │ 消费事件队列
┌──────────────▼───────────────────────────────────────────────────┐
│  Monitor（单协程，每 10s 一轮）                                    │
│  ① 采集 Puller 指标（state, fetched, empty_polls, backpressure）  │
│  ② 采集队列指标（queue_size, saturation）                          │
│  ③ 采集 BrowserPool 指标（alive/busy/dead/stuck/crashed）         │
│  ④ 消费 Worker 事件队列（成功计数 / 失败写入 task_failures）        │
│  ⑤ 采集系统资源（CPU/内存 psutil）                                  │
│  ⑥ 数据库健康检查（MySQL/Redis/MongoDB ping）                      │
│  ⑦ 输出报告日志 + WS system_status 广播（1s 节流）                 │
│  ⑧ 崩溃自愈：检测 dead Worker → 自动重启 + WS worker_crash 广播    │
└──────────────────────────────────────────────────────────────────┘
```

### 5.2 Puller 状态机与参数

```
PullerState: INITIALIZED → RUNNING ↔ BACKPRESSURE → STOPPED

配置（PullerConfig, 环境变量前缀 PULLER_）:
  backpressure_high: 0.8        队列饱和度进入背压水位线
  backpressure_low:  0.6        退出背压水位线
  base_sleep:        0.1s       无任务初始休眠
  max_sleep:         5.0s       指数退避上限
  backpressure_sleep: 0.5s      背压态固定休眠
  batch_size:        10         单次批量弹出数
  task_cooldown_seconds: 2.0s   相邻任务最小间隔（ZSET score 错开）
  worker_rest_min:   150s       Worker 执行后最少休息
  worker_rest_max:   250s       Worker 执行后最多休息
```

### 5.3 Worker 反爬错峰

```
5 个 Worker 各自独立:
  Worker 0: 取任务 → jitter=137s → 执行(~25s) → rest~180s → 取下一个
  Worker 1: 取任务 → jitter=284s → 执行(~25s) → rest~220s → 取下一个
  ...自然错峰，豆瓣视角始终是单线程低频访问
```

### 5.4 失败事件处理链路

```
Worker 捕获异常
  → classify_exception(exc) → FailureKind(NETWORK/TIMEOUT/HTTP/PARSE/STORAGE/ABUSE/…)
  → WorkerEvent(type=FAILURE, kind=…, worker_id, task, reason, timestamp)
  → event_queue.put(event.model_dump())
  ↓
Monitor._drain_events()
  → WorkerEvent.model_validate(raw)
  → _write_failure_event(event)
      → INSERT INTO task_failures（18 列，scope=batch/item，含 failure_layer）
      → ws_manager.push(admin_id, {type:"task_failure", …})  → 前端弹窗
```

## 十、认证鉴权全链路

### 10.1 认证流程

```
┌─────────────────────────────────────────────────────────────────┐
│ ① 登录                                                          │
│                                                                  │
│  POST /auth/login { username, password }                        │
│    ├─ 限流检查：同一 IP 60s 内最多 5 次（Redis 滑动窗口 + Lua）   │
│    ├─ AuthService.authenticate()                                │
│    │   ├─ get_user_by_username() → 查 users 表                   │
│    │   ├─ bcrypt.checkpw(password, password_hash) → 密码校验     │
│    │   └─ is_active 检查 → 禁用则抛 UserDisabledError            │
│    ├─ AuthService.create_token(user_id)                         │
│    │   └─ jwt.encode({ sub, iat, exp }, JWT_SECRET, HS256)      │
│    ├─ AuthService.get_user_permissions(user_id)                  │
│    └─ 返回 { token, user: { id, uuid, username, avatar_url, permissions } } │
│                                                                  │
│ ② 后续请求                                                       │
│                                                                  │
│  每个 HTTP 请求 → Authorization: Bearer <JWT>                    │
│    ├─ get_current_user()                                        │
│    │   ├─ 提取 header["Authorization"][7:]                       │
│    │   ├─ AuthService.verify_token(token)                        │
│    │   │   └─ jwt.decode(token, JWT_SECRET) → user_id            │
│    │   │   └─ ExpiredSignatureError → None                       │
│    │   ├─ AuthService.get_user(user_id) → 查 users 表             │
│    │   └─ 检查 is_active → True=返回 user_id / False=返回 0       │
│    └─ g.user_id = user_id（Quart ContextVar 请求级隔离）         │
│                                                                  │
│ ③ 权限校验                                                       │
│                                                                  │
│  @require_permission("movie:manage")                             │
│    ├─ get_current_user() → user_id（0=未登录）                    │
│    ├─ 0 → 401 { "error": "未登录或登录已过期" }                   │
│    ├─ AuthService.check_permission(user_id, code)                │
│    │   └─ SELECT 1 FROM user_permissions WHERE …                 │
│    ├─ False → 403 { "error": "无权限: movie:manage" }            │
│    └─ True → g.user_id = user_id → 执行 handler                  │
│                                                                  │
│  @require_login                                                  │
│    └─ 同上但不查权限表，仅校验登录状态                              │
└─────────────────────────────────────────────────────────────────┘
```

### 10.2 密码安全

```
注册 / 管理员创建用户:
  password (明文) → bcrypt.hashpw(password, gensalt(rounds=12)) → password_hash
  → INSERT INTO users (password_hash)

登录:
  password (明文) → bcrypt.checkpw(password, password_hash) → True/False

JWT:
  palyload: { sub: str(user_id), iat: 当前时间(CST), exp: iat + 7天 }
  算法: HS256
  密钥: settings.JWT_SECRET（必须通过 .env 显式设置，默认为空=启动拒绝）
```

### 10.4 权限表设计（3 表）

```
users ──1:N── user_permissions ──N:1── permissions
  id              user_id                code (PK)
  uuid            permission_code        name
  username        granted_by             description
  password_hash   granted_at
  avatar_url
  display_name
  is_active

权限分配流程:
  POST /admin/users/<id>/permissions { permission_codes: [...] }
    → AuthService.set_permissions(data)
      → BEGIN TRANSACTION
      → DELETE FROM user_permissions WHERE user_id = ?
      → INSERT INTO user_permissions (user_id, permission_code, granted_by) × N
      → COMMIT
```

### 10.5 统一异常体系

```
ServiceError (基类)
  ├─ BadRequestError (400)
  ├─ UnauthorizedError (401)
  │   ├─ AuthenticationError — 用户名或密码错误
  │   └─ UserDisabledError — 账户已被禁用 (code=USER_DISABLED)
  ├─ ForbiddenError (403)
  ├─ NotFoundError (404) — 资源不存在: {resource} {identifier}
  ├─ ConflictError (409)
  │   └─ DuplicateError — 资源已存在 (code=DUPLICATE)
  └─ TooManyRequestsError (429) — 请求频率超限

路由层统一处理:
  try:
      result = await service.method(...)
  except ServiceError as e:
      return jsonify({"error": e.message, "code": e.code}), e.status_code
```
