## 二、用户行为定义

### 2.1 操作枚举

| id | 操作 | 英文 | action_weight | 触发条件 | 同一电影可重复 |
|:--:|------|------|:--:|------|:--:|
| 1 | 想看 | `want_watch` | 1.0 | 无条件 | ❌ |
| 2 | 在看 | `watching` | 1.2 | 无条件 | ❌ |
| 3 | 看过 | `watched` | 2.0 | 无条件 | ❌ |
| 4 | 收藏 | `favorite` | 1.5 | **独立**，不限观看状态 | ❌ |
| 5 | 评论 | `comment` | 3.0 | **必须先标记"看过"** | ❌ |

### 2.2 观看状态机

```
        想看(1.0×)        在看(1.2×)        看过(2.0×)
           │                  │                  │
           ▼                  ▼                  ▼
    ┌──────────┐ 在看  ┌──────────┐ 看过  ┌──────────┐
    │  想看    │ ───→ │  在看    │ ───→ │  看过    │
    │ want_    │      │ watching │      │ watched  │
    │ watch    │ ←─── │          │      │          │
    └────┬─────┘ 想看  └────┬─────┘      └────┬─────┘
         │                  │                  │
         │    取消          │    取消           │    取消
         ▼                  ▼                  ▼
      (无副作用)         (无副作用)       分数回滚 + 观看标记清空
                                         收藏不受影响
                                         评论不受影响
```

- **递进覆盖**：想看(+1.0) → 在看(+1.2) → 看过(+2.0)，替换前一次加分
- **退回覆盖**：取消任何一级直接回到 0 分，不支持退到前一级
- **取消"看过"**：清空 `want_watch/watching/watched`，**不改变 `favorite`**，**不改变已发评论**

### 2.3 收藏（独立于观看状态）

| 场景 | 是否允许 |
|------|:--:|
| 无任何标记 → 收藏 | ✅ |
| 已看过 → 收藏 | ✅ |
| 已收藏 → 取消收藏 | ✅ |
| 取消"看过" → 收藏状态 | ✅ 不变 |

### 2.4 评论（特殊规则）

| 规则 | 说明 |
|------|------|
| 前提 | 必须先标记 `watched` |
| 幂等 | 同一电影最多一条有效评论 |
| 文本必填 | 无文本时拒绝提交（`400 EMPTY_REVIEW_TEXT`） |
| 评分可选 | 不打星→中性（不改变画像）；打星→影响标签分（见下方） |
| 分数 | `effective_weight × SUM`，见下方 `rating_factor` 公式 |
| 删除 | is_published=false, removed_by='user' |
| 删除后 | **分数回滚**，不可恢复 |
| 管理员下架 | is_published=false, removed_by='admin'，**不触发分数回滚** |
| 恢复 | 仅 `removed_by='admin'` 可恢复 |

> **v1.1 新增** — 评分调节因子

评论操作的 effective_weight 受用户打分调节：

```
effective_weight = action_weight × rating_factor(rating)

rating_factor = factor_max × (rating - neutral) / (5.0 - neutral)    当 rating ≥ neutral
rating_factor = factor_min × (neutral - rating) / (neutral - 1.0)    当 rating < neutral
rating_factor = 0.0                                                   当 rating 为 None
```

| 评分 | factor（默认） | effective_weight | 语义 |
|:--:|:--:|:--:|------|
| ⭐⭐⭐⭐⭐ | +1.00 | +3.00 | 强烈喜欢 |
| ⭐⭐⭐⭐ | +0.50 | +1.50 | 比较喜欢 |
| ⭐⭐⭐ | 0.00 | 0.00 | 中性，不改变画像 |
| ⭐⭐ | -0.25 | -0.75 | 不太喜欢 |
| ⭐ | -0.50 | -1.50 | 反感，降低该类型 |
| 不评分 | 0.00 | 0.00 | 不改变画像 |

配置项（`config_score_weight` 表，热加载）：

| config_key | 默认值 | 说明 |
|------------|:--:|------|
| `comment.rating_neutral` | 3.0 | 中性点（factor=0 的基准） |
| `comment.rating_factor_max` | 1.0 | 5星对应因子上限 |
| `comment.rating_factor_min` | -0.5 | 1星对应因子下限（保守非对称） |

> **设计理由**：差评惩罚设为 5 星的一半（-0.5 vs +1.0），因为「不喜欢」比「喜欢」更难量化。后续可根据数据 `UPDATE config_score_weight` 热调整。

## 三、数据库设计

### 3.1 `user_movie_status` — 用户-电影标记状态（快照）

```sql
CREATE TABLE user_movie_status (
    user_id       INT      NOT NULL COMMENT 'FK users.id',
    movie_id      BIGINT   NOT NULL COMMENT 'FK movies.id',
    want_watch    TINYINT  NOT NULL DEFAULT 0 COMMENT '1=想看',
    watching      TINYINT  NOT NULL DEFAULT 0 COMMENT '1=在看',
    watched       TINYINT  NOT NULL DEFAULT 0 COMMENT '1=看过',
    favorite      TINYINT  NOT NULL DEFAULT 0 COMMENT '1=收藏',
    updated_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (user_id, movie_id),
    INDEX idx_user_want   (user_id, want_watch),
    INDEX idx_user_watched(user_id, watched),
    INDEX idx_user_fav    (user_id, favorite)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户-电影标记状态（当前快照）';
```

**设计理由**：四个 TINYINT 而非 ENUM，因为 `favorite` 独立于观看状态，不能互斥。

**取消"看过"时的 SQL**（保留 favorite）：
```sql
UPDATE user_movie_status 
SET want_watch=0, watching=0, watched=0
WHERE user_id=? AND movie_id=?;
-- favorite 字段不变
```

### 3.2 `user_action_log` — 操作流水（审计 + 回滚依据）

```sql
CREATE TABLE user_action_log (
    id              BIGINT       NOT NULL COMMENT 'snowflake ID',
    user_id         INT          NOT NULL COMMENT 'FK users.id',
    movie_id        BIGINT       NOT NULL COMMENT 'FK movies.id',
    action          VARCHAR(16)  NOT NULL COMMENT 'want_watch|watching|watched|favorite|comment',
    score_delta     DECIMAL(8,4) NOT NULL DEFAULT 0 COMMENT '本次操作总计分值（正=加分，负=扣分）',
    tag_deltas_json JSON         COMMENT '[{"dim":"director","label":"吕克·贝松","delta":2.0},...]',
    reverted_at     DATETIME     DEFAULT NULL COMMENT '非空=已回滚',
    created_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    INDEX idx_user_movie   (user_id, movie_id),
    INDEX idx_user_time    (user_id, created_at DESC),
    INDEX idx_reverted     (reverted_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户行为操作流水（审计+回滚）';
```

**`tag_deltas_json` 作用**：回滚时精确取反每个标签的 `delta`，无需重算 MovieContext。

**评论幂等约束**（应用层）：
```python
existing = await db.fetch_one(
    "SELECT 1 FROM user_action_log "
    "WHERE user_id=%s AND movie_id=%s AND action='comment' AND reverted_at IS NULL",
    (user_id, movie_id)
)
if existing:
    return 409, {"error": "已评论过该电影"}
```

### 3.3 `user_tag_score` — 用户-标签分数聚合（画像查询）

```sql
CREATE TABLE user_tag_score (
    user_id       INT          NOT NULL COMMENT 'FK users.id',
    dimension     VARCHAR(16)  NOT NULL COMMENT 'era|region|director|actor|genre|overall|plot|visual|narrative|pacing',
    label         VARCHAR(128) NOT NULL COMMENT '标签文本（冗余，加速单表查询）',
    score         DECIMAL(8,4) NOT NULL DEFAULT 0 COMMENT '当前累积分值',
    last_action   VARCHAR(16)  DEFAULT NULL COMMENT '最后一次触发此标签的操作类型',
    updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (user_id, dimension, label),
    INDEX idx_user_score (user_id, score DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户-标签分数聚合快照';
```

**为什么冗余 label**：导演名在 `people` 表、AI 标签名在 `movie_style_tag` 表。不冗余的话查用户画像要 JOIN 3~4 张表。冗余后单表单索引，毫秒级返回。

## 四、分数公式

### 4.1 单标签增量

```
score_delta = effective_weight × dim_weight × actor_decay × confidence

  effective_weight = action_weight × rating_factor(rating)  ← 仅 comment（v1.1）
                     action_weight                           ← 其他操作

  action_weight  ← config_score_weight.config_key = 'action.{action}'
  rating_factor  ← 见 §2.4（仅 comment 操作生效，保守非对称映射）
  dim_weight     ← config_score_weight.config_key = 'dim.{dimension}'
  actor_decay    ← config_score_weight.config_key = 'actor.decay.{position}'  (仅 actor 维度)
  confidence     ← 豆瓣数据 = 1.0
                    AI 数据 = movie_style.confidence (0.5~1.0)
```

**三者互不冗余**：

| 砍掉 | 后果 |
|------|------|
| `action_weight` | 收藏(1.5)和看过(2.0)权重相同，区分不了投入度 |
| `dim_weight` | 年代(0.3)和导演(1.0)标签一样重，看了 5 部 1990s 和 5 部吕克·贝松一个效果 |
| `confidence` | AI 说"可能是"和"肯定是"加分一样多 |

### 4.2 单次操作总加分

```
action_total = SUM(每个标签的 score_delta)
```

存入 `user_action_log.score_delta` 和 `user_action_log.tag_deltas_json`。

### 4.3 时间衰减（查询时计算，不写死存储）

```sql
SELECT 
  dimension, label,
  SUM(
    score_delta * 
    CASE 
      WHEN created_at > NOW() - INTERVAL 30 DAY  THEN 1.0
      WHEN created_at > NOW() - INTERVAL 90 DAY  THEN 0.8
      WHEN created_at > NOW() - INTERVAL 180 DAY THEN 0.5
      ELSE 0.2 
    END
  ) AS decayed_score
FROM user_action_log
WHERE user_id = ? AND reverted_at IS NULL
GROUP BY dimension, label
ORDER BY decayed_score DESC
```

### 4.4 分数与标签权重的关系

```
tag_weight（电影画像） ≠ score_delta（用户画像）

tag_weight 回答 "这个标签对这部电影多重要"
score_delta 回答 "用户这次操作对每个标签积累了多少分"

score_delta 的计算依赖 tag_weight，但它们是两个独立概念。
```

## 六、操作生命周期（完整状态机）

### 6.1 观看标记递进（想看 → 在看 → 看过）

```
① POST /movies/38/want-watch
  → INSERT user_movie_status (want_watch=1)
  → INSERT user_action_log (action='want_watch', score_delta=+SUM)
  → UPSERT user_tag_score (score += ①.delta)

② POST /movies/38/watching          ← 从"想看"递进到"在看"
  → UPDATE user_movie_status SET want_watch=0, watching=1
  → INSERT user_action_log (action='watching', score_delta=+SUM)
  → 回滚①: INSERT user_action_log (action='want_watch', score_delta=-①.delta, reverted_at=NOW())
  → UPSERT user_tag_score (score += ②.delta - ①.delta)

③ POST /movies/38/watched           ← 从"在看"递进到"看过"
  → UPDATE user_movie_status SET watching=0, watched=1
  → INSERT user_action_log (action='watched', score_delta=+SUM)
  → 回滚②: INSERT user_action_log (action='watching', score_delta=-②.delta, reverted_at=NOW())
  → UPSERT user_tag_score (score += ③.delta - ②.delta)
```

### 6.2 取消看过

```
④ DELETE /movies/38/watched
  → UPDATE user_movie_status SET want_watch=0, watching=0, watched=0
     (favorite 不动)
  → INSERT user_action_log (action='watched', score_delta=-③.delta, reverted_at=NOW())
  → UPSERT user_tag_score (score -= ③.delta)
  → 评论不受影响
```

### 6.3 收藏（独立）

```
POST /movies/38/favorite
  → UPDATE user_movie_status SET favorite=1
  → INSERT user_action_log (action='favorite', score_delta=+SUM)
  → UPSERT user_tag_score (score += delta)

DELETE /movies/38/favorite
  → UPDATE user_movie_status SET favorite=0
  → INSERT user_action_log (action='favorite', score_delta=-SUM, reverted_at=NOW())
  → UPSERT user_tag_score (score -= delta)
```

### 6.4 评论

```
POST /movies/38/comment
  → 校验: SELECT watched FROM user_movie_status → 0 → 403 "请先标记看过"
  → 校验: SELECT 1 FROM user_action_log WHERE action='comment' AND reverted_at IS NULL → 1 → 409 "已评论过"
  → MongoDB: INSERT comment (_id="user_1_movie_38", user_id=1, is_published=true)
  → 计算 effective_weight = action_weight × rating_factor(rating)    ← v1.1
  → INSERT user_action_log (action='comment', score_delta=effective_weight×SUM)
  → UPSERT user_tag_score (score += delta)   ← delta 可为正/零/负

DELETE /movies/38/comment
  → MongoDB: UPDATE SET is_published=false, removed_by='user'
  → INSERT user_action_log (action='comment', score_delta=-orig_delta, reverted_at=NOW())
  → UPSERT user_tag_score (score -= orig_delta)   ← 自动取反，正负均可回滚
  → 删除后不可恢复

管理员下架（不在此子系统内）:
  → MongoDB: UPDATE SET is_published=false, removed_by='admin'
  → 不影响 user_tag_score
```

## 七、数据写入链路（MovieContext 集成）

```
用户操作 (POST /user/movies/38/watched)
  ↓
① 校验 user_movie_status (幂等 / 递进)
  ↓
② 查询 MovieContext.build(movie_id=38)  → 12 个 tag
  ↓
③ 逐个计算 score_delta:
      action_weight(2.0) × dim_weight × actor_decay × confidence
  ↓
④ 开启事务:
    ├─ user_movie_status 更新
    ├─ user_action_log 插入 (含 tag_deltas_json)
    ├─ user_tag_score UPSERT × 12  (score += delta)
    └─ 递进场景: 回滚前一级的 user_action_log
  ↓
⑤ 提交 → 返回 200 { action, movie_id, score_total, tag_count }
```

**评论操作的特殊路径（v1.1）**：

```
POST /user/movies/38/comment { review_text: "...", rating: 1 }
  ↓
③ effective_weight = action_weight(3.0) × rating_factor(1.0) = -1.5
   delta = effective_weight × tag.weight   ← 结果可为负数
  ↓
④ 事务: user_action_log 插入 (score_delta 可为负)
         user_tag_score 扣分 (score -= 1.5 × tag.weight)
         comment 不更新 user_movie_status
  ↓
⑤ 若用户删除评论 → rollback: score_delta 取反 → user_tag_score 加回
```

## 八、注意事项

| 项 | 说明 |
|----|------|
| **配置热加载** | `config_score_weight` 表 UPDATE 后，下次 `get_user_tag_profile` 查询时重新读取 |
| **词云兼容** | 用户评论混入 MongoDB comments，按 `is_published=true` 过滤，天然兼容现有词云逻辑 |
| **并发安全** | `user_tag_score` 用 `INSERT ... ON DUPLICATE KEY UPDATE score=score+%s`，非 SELECT-then-UPDATE |
| **事务边界** | `user_movie_status` + `user_action_log` + `user_tag_score` 在同一 MySQL 事务中 |
| **MongoDB 与 MySQL** | 评论写入 MongoDB 不在 MySQL 事务内。先写 Mongo 成功再写 MySQL，Mongo 失败则拒绝操作 |
| **取消看过不清收藏** | `UPDATE SET want_watch=0,watching=0,watched=0` 不碰 favorite |
| **评论评分调节** | **v1.1** `comment.rating_*` 三个配置项热加载，控制评分→因子映射 |
| **user_tag_score 可为负** | **v1.1** 差评导致 delta 为负，`score += delta` 自动扣分；MySQL `DECIMAL` 天然支持负数 |
| **回滚兼容** | 滚时从 `tag_deltas_json` 取反写入，正负均可正确回滚，无需区分 |

## 九、推荐系统 — 基于变异系数的自适应内容推荐

### 9.1 设计理念

```
用户在意的维度（CV 高）→ 精准投其所好
用户不在意的维度（CV 低）→ 随机探索，打破信息茧房
```

不依赖协同数据、不训练模型，直接从 `user_tag_score` 表用 SQL 聚合 + 应用层排序即可出结果。

### 9.2 变异系数在此场景的语义

```
用户A 看了 10 部电影：
  导演标签: 吕克·贝松=8.0, 诺兰=1.0, 宫崎骏=0.5, 其他7个导演=0.1~0.5
  → μ=1.6, σ=2.7, CV=1.69 🔴 高离散 — 有明显偏好

  年代标签: 1990s=2.0, 2000s=1.8, 2010s=2.1, 1980s=1.5, 1970s=1.2
  → μ=1.72, σ=0.32, CV=0.19 🟢 低离散 — 什么年代都看
```

| 维度 | CV | 含义 | 推荐策略 |
|------|:--:|------|------|
| 导演 | 1.69 | 用户很挑导演 | **精准匹配**，推高分导演的作品，避开低分导演 |
| 年代 | 0.19 | 用户不挑年代 | **探索模式**，偏随机或按维度权重均匀分配 |

### 9.3 算法步骤

**Step 1 — 计算每个维度的变异系数**

```
对每个维度 d ∈ {era, region, director, actor, genre, overall, plot, visual, narrative, pacing}:

  tags_d = {tag ∈ user_tag_score | dimension=d, user_id=当前用户}

  如果 |tags_d| ≤ 1:
    CV_d = 0  ← 样本太少，无法判断偏好，退化为探索模式

  否则:
    scores = [tag.score for tag in tags_d]
    μ_d = mean(scores)
    σ_d = std(scores)
    CV_d = σ_d / μ_d      if μ_d > 0
    CV_d = 0              if μ_d = 0 (未接触该维度)
```

**Step 2 — 对候选电影打分**

```
候选电影集: 所有 is_published=1 且 id NOT IN (用户已观看的电影ID列表)

对每部候选电影 m:
  movie_context = MovieContext.build(m.id)

  score_m = SUM over dimensions d:

    if CV_d > cv_threshold:
      → 精准模式
      匹配分 = SUM( user_tag_score[tag.label] for tag in movie_context.tags
                    where tag.dimension=d and tag.label 存在于 user_tag_score )

    else:
      → 探索模式
      匹配分 = random(0, 1) × dim_weight_d
```

**Step 3 — 排序 + 截断 top-10**

```
ranked = sorted(候选电影, key=score_m, reverse=True)
return ranked[:10]
```

### 9.4 完整评分公式

```
score_movie(m, user) =
  SUM over dimensions d:
    if CV_d > cv_threshold:
      SUM over tags t in m where dimension=t.dimension:
        user_tag_score.get(t.label, 0) × t.confidence
    else:
      random(0, 1) × dim_weight_d

  其中:
    CV_d           ← 用户维度 d 的变异系数
    cv_threshold   ← 判定"有明显偏好"的阈值，配置在 config_score_weight
    dim_weight_d   ← config_score_weight[dim.{d}]
    confidence     ← 豆瓣=1.0, AI=movie_style.confidence (0.5~0.9)
```

### 9.5 边界条件

| 场景 | 处理方式 |
|------|------|
| **单标签维度** | 用户只接触过"法国" → tags_d 只有 1 个值 → CV=0 → 探索模式 |
| **零分标签** | 用户未接触过"惊悚" → user_tag_score 无此标签 → 匹配分为 0，不扣分 |
| **分数回滚后** | 用户删除评论 → 标签分数降低 → CV 变小 → 从精准退化为探索 |
| **冷启动** | 新用户无 user_tag_score → 所有 CV=0 → 全部探索模式 + 热门电影兜底 |
| **推荐可解释性** | 可展示 "因为你对导演有强烈偏好，推荐了吕克·贝松的作品" |

### 9.6 新增配置

```sql
INSERT INTO config_score_weight (config_key, config_value, description) VALUES
('recommend.cv_threshold', 0.5, '变异系数阈值: 高于此值走精准推荐，低于走探索');
```
