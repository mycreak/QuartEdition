## 六、规划中 — 用户/管理员个人详情页

> 最后更新：2026-05-11
> 状态：**待后端配合实现**（目前 users 表无 avatar 字段，无自编辑端点）

---

### 6.1 功能概述

为 **普通用户** 和 **管理员** 提供个人详情页，支持：
- 查看个人信息
- 编辑头像（上传图片）
- 编辑昵称（display_name）

### 6.2 依赖的后端改造（需优先完成）

| # | 后端需求 | 说明 |
|:-:|---------|------|
| ① | `users` 表增加 `avatar_url` 字段 | 存储头像图片 URL（可空字符串） |
| ② | 文件上传端点 `POST /upload/avatar` | 接收图片文件 → 保存 → 返回 URL |
| ③ | 用户自编辑端点 `PATCH /auth/me` | 支持更新 `display_name`、`avatar_url` |
| ④ | `GET /auth/me` 返回 `avatar_url` | 当前用户信息包含头像字段 |
| ⑤ | 管理端 `PATCH /admin/users/<id>` 扩展 `avatar_url` | 管理员可为其他用户设置头像 |

> 当前 UserRead 模型字段：`id`, `uuid`, `username`, `display_name`, `is_active`, `created_at`, `updated_at`（无 avatar_url）

### 6.3 前端新增文件清单

| 文件 | 类型 | 职责 |
|------|------|------|
| `src/api/profile.ts` | API 封装 | `PATCH /auth/me` + `POST /upload/avatar` |
| `src/views/user/ProfileView.vue` | 用户端页面 | 普通用户个人详情页（头像 + 昵称编辑） |
| `src/views/admin/AdminProfileView.vue` | 管理端页面 | 管理员个人详情页（同上 + 更多管理入口） |
| `src/components/common/AvatarUpload.vue` | 通用组件 | 头像裁剪/上传/预览（用户端和管理端共用） |

### 6.4 前端需修改的文件

| 文件 | 改动内容 |
|------|---------|
| `src/types/auth.ts` | `User` 接口增加 `avatar_url?: string` |

### 6.5 前端数据流

```
用户点击头像/昵称 → 下拉菜单「个人中心」
  → 路由跳转 /profile（或 /admin/profile）
  → ProfileView 加载
      ├─ GET /auth/me 获取当前用户信息（含 avatar_url）
      ├─ AvatarUpload 组件
      │    └─ 选择图片 → POST /upload/avatar → 返回 URL → 预览
      └─ 昵称编辑表单
           └─ 输入新昵称 → PATCH /auth/me → 更新 store → 刷新 header
```

### 6.6 关键设计点

| 决策点 | 建议方案 | 原因 |
|--------|---------|------|
| 头像存储 | 后端本地存储 + URL 返回（Nginx 静态代理） | 项目无云存储依赖，简单可靠 |
| 头像裁剪 | el-upload + 前端 canvas 裁剪后上传 | 避免上传大图，减少带宽 |
| 昵称校验 | 1-64 位，与注册时一致 | 后端 `UserUpdate.display_name` 已有校验 |
| 权限控制 | `/profile` 只需登录（requiresAuth）；`/admin/profile` 需任意管理权限 | 管理员个人页面可额外展示管理快捷入口 |
| store 同步 | `updateProfile()` 成功后更新 `authStore.user` | 确保 header 头像/昵称即时刷新 |

## 五、关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| WS 连接管理 | App.vue 持有生命周期 | 全局单例，未进入 /admin 时也能收到通知（积压机制） |
| WebSocket 心跳 | 30s ping/pong | 后端 nginx/负载均衡超时一般为 60s，30s 足够保活 |
| WS 重连策略 | 指数退避 1s→max 30s | 避免频繁重连打满服务端 |
| 仪表盘 WS 节流 | 1s | Monitor 每 10s 广播，1s 节流避免无谓渲染 |
| queue 详情 | 开关按钮 + `?details=1` | 默认 4 字段快速加载，按需请求详情 |
| 电影 ID 下拉 | el-autocomplete + `is_acquired=1` | 可搜索、可自由输入、仅展示已认领的 ID |
| 自禁用保护 | 前端 `username` 比对拦截 | 双重保护，后端也有 `SELF_DISABLE_FORBIDDEN` |
| 登录响应处理 | 存 token → fetchUser() | `/auth/login` 不返回 permissions，`/auth/me` 才返回完整信息 |
