# 前端架构概览

> Vue 3 + TypeScript + Pinia + Vue Router + Element Plus
> 合并自：Phase 1/2/3 逻辑地图 + 分层执行路线图

---

## 一、启动流程

```
index.html → <div id="app"> + <script src="/src/main.ts">

main.ts
  ├─ createApp(App)
  ├─ app.use(createPinia())        ← 必须在 Router 之前
  ├─ app.use(ElementPlus)          ← UI 库
  ├─ 批量注册 Element Plus Icons   ← 全局图标组件
  ├─ setupGuards(router)           ← 注册路由守卫
  ├─ app.use(router)               ← 注册 Router
  └─ app.mount('#app')
```

## 二、模块依赖关系

```
src/types/        ← 纯类型层，0 运行时代码
  api.ts / auth.ts / movie.ts / review.ts / task.ts / failure.ts / status.ts

src/utils/        ← 纯函数，不依赖 Pinia
  permission.ts   → PERMISSION_CODES + hasPermission()
  format.ts       → formatRating / formatDate / formatCount

src/api/          ← axios 封装，依赖 types
  client.ts       → axios 实例（请求拦截加 token，响应拦截 401 跳转登录）
  ws.ts           → WsManager 单例（连接/心跳/重连/事件分派）
  auth.ts         → login / register / me
  movies.ts       → list / detail（用户端）
  user.ts         → filterPacket / reviews / comments / genres
  admin/
    monitor.ts    → status / queue（含 details） / logs / rateLimit
    tasks.ts      → submit（5 种类型） / list / taskHistory
    failures.ts   → list / detail / claim / release / resolve / retry
    movies.ts     → list / detail / publish / unpublish
    reviews.ts    → reviews / comments / publish / unpublish
    users.ts      → list / create / update / assignPermissions
    douban_ids.ts → list / add / acquire / release
    infra.ts      → proxies CRUD + health-check + cookies status/replace

src/stores/       ← Pinia，依赖 api + types
  auth.ts         → user / token / isAdmin / login / logout / fetchUser / checkPermission
  movies.ts       → movies / total / filters / fetchList / fetchDetail

src/router/
  index.ts        → 路由表（15 条，全部懒加载）
  guards.ts       → beforeEach: token → fetchUser → permission check
```

**关键约束**：
- 组件不直接调 `axios`，全部通过 `src/api/` 封装
- 组件不直接读写 `localStorage`，全部通过 `authStore`
- 类型定义只写一次在 `src/types/`，API 封装和组件共享

## 四、权限模型

```typescript
// src/utils/permission.ts
const PERMISSION_CODES = [
  'user:manage', 'crawler:task:read', 'crawler:task:write',
  'crawler:failure:manage', 'movie:manage', 'movie:read',
  'comment:read', 'comment:manage', 'system:monitor',
] as const;

// authStore 提供:
isAdmin: boolean          // 有 user:manage = 超管
permissions: string[]     // 用户拥有的权限列表
checkPermission(code): boolean  // 查单条
```

**侧边栏按权限渲染**（AdminLayout）：
- 仪表盘 / 爬虫面板 → `system:monitor`
- 失败任务 → `crawler:failure:manage`
- 豆瓣电影 ID → `crawler:task:read`
- 电影管理 → `movie:manage` | `movie:read`
- 评论管理 → `comment:manage` | `comment:read`
- 用户管理 → `user:manage`（仅超管可见）
- 基础设施（代理 + Cookie）→ `system:monitor`

## 五、认证流程

```
用户输入密码登录
  → POST /auth/login → { token, user }
  → localStorage.set('token')
  → router.push('/')

页面刷新 / 新标签页
  → beforeEach 守卫
  → localStorage 有 token?
    → GET /auth/me → 填充 authStore.user + permissions
    → 放行
  → 无 token?
    → 目标路由需登录? → 跳 /login
    → 公开路由? → 放行

401 拦截（api/client.ts 响应拦截）
  → localStorage.clear('token')
  → authStore.$reset()
  → router.push('/login')
```

**一个需要注意的地方**：`fetchUser` 失败（网络断连）时不主动清除 token，保留登录态下次重试。仅 401 时才清除。
