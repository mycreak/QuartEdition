# 论文摘要材料

## 一、功能概览

- 本项目面向电影信息聚合、影评数据管理与后台爬虫调度场景，设计并实现了一套前后端分离的电影数据管理与展示系统。

- 系统主要包含用户端、管理端和后台数据采集模块三大部分，支持普通用户浏览电影信息、查看电影详情、检索筛选影片、查看长评与短评，并通过词云等方式直观展示用户评论热点。

- 用户端提供注册、登录、个人资料维护、头像上传、电影列表浏览、电影详情查看、影评聚合展示、类型与评分筛选等功能，提升用户对电影数据的查询和阅读体验。

- 管理端提供电影数据维护、评论上下架、用户管理、权限分配、豆瓣电影 ID 管理、爬虫任务提交、任务进度查看、失败任务处理、代理与 Cookie 管理、系统监控等功能，便于管理员对系统运行和数据质量进行统一管理。

- 后台模块支持电影基础信息、演职人员、地区、类型、评分、长评、短评等多维度数据采集，并通过任务队列、失败记录、任务历史、状态监控等机制提高数据采集过程的可靠性和可追溯性。

- 系统引入 WebSocket 实时通信机制，用于向管理端推送任务失败、工作协程异常、任务状态变化等事件，使管理员能够及时掌握后台任务运行情况。

- 系统还支持图片上传与对象存储，包括用户头像上传、电影海报上传与图片裁剪处理，增强了系统内容维护能力。

## 二、业务详解

### 1. 用户业务

- 用户可以通过注册与登录进入系统，系统采用基于令牌的身份认证机制，保证访问过程的安全性。

- 登录用户可以浏览已发布的电影列表，并根据电影名称、类型、评分区间等条件进行检索和筛选，从而快速定位感兴趣的影片。

- 在电影详情页中，用户可以查看电影的基础信息、评分信息、演职人员信息、地区和类型信息，同时可以查看对应的长评和短评内容。

- 系统对短评内容进行聚合分析，并以词云形式展示高频关键词，使用户能够快速了解影片评论中的主要观点和情感倾向。

- 用户可以进入个人中心修改昵称、上传头像、维护个人基础信息，系统通过前端表单校验和后端数据校验保证用户资料的规范性。

### 2. 管理业务

- 管理员可以对电影数据进行新增、查询、编辑、上下架等操作，维护电影的基础资料、海报、演职人员、类型、地区和评分信息。

- 管理员可以管理评论内容，包括查看长评和短评、控制评论是否展示，从而保证前台展示内容的质量和合规性。

- 系统支持用户管理与权限分配，管理员可以创建用户、禁用或恢复用户、修改用户信息，并根据业务角色分配不同权限。

- 管理端提供豆瓣电影 ID 资产管理功能，支持添加、认领、释放和查看电影 ID 状态，保证爬虫任务的数据来源有序可控。

- 系统提供基础设施管理能力，包括代理池管理和 Cookie 管理。管理员可以对代理和 Cookie 进行新增、测试、禁用、恢复和状态查看，以提高爬虫稳定性和反爬应对能力。

### 3. 爬虫与任务业务

- 系统内置电影数据采集模块，支持从外部电影平台采集电影基础信息、评分、演职人员、长评、短评等数据。

- 爬虫任务采用后台异步调度方式运行，用户请求与数据采集任务相互解耦，避免长时间爬取任务阻塞 Web 接口。

- 系统通过 Redis 延迟队列维护待执行任务，并结合后台 Puller、Worker 和 Monitor 协程实现任务拉取、执行和监控。

- 每个任务在执行过程中会记录任务历史和执行状态，包括任务类型、参数、执行结果、耗时、失败原因等信息，便于后续追踪和问题定位。

- 对于执行失败的任务，系统建立失败任务管理机制，支持失败记录查看、认领、释放、解决和重新爬取，提高后台任务的容错能力。

- 系统通过代理池、Cookie 管理、身份绑定、请求限流、任务去重等策略降低爬虫被限制的风险，并提升批量采集过程的稳定性。

### 4. 数据管理业务

- 系统采用关系型数据库和文档型数据库结合的方式进行数据存储。电影、用户、权限、任务历史等结构化数据存储在 MySQL 中，长评和短评等半结构化文本数据存储在 MongoDB 中。

- Redis 用于任务队列、登录注册限流、爬虫任务去重、词云缓存等场景，提高系统响应速度和后台调度效率。

- 电影数据模型覆盖电影基础信息、人员信息、类型、地区、评分、评论、任务、用户与权限等多个业务实体，能够支撑完整的电影数据管理流程。

- 系统为关键业务数据建立历史记录和状态字段，例如电影上下架状态、豆瓣 ID 认领状态、任务执行状态和失败处理状态，从而保证业务过程可追溯。

## 三、技术栈介绍

### 1. 前端技术栈

- 前端采用 Vue 3 作为核心框架，结合 Composition API 和 `<script setup>` 语法组织页面逻辑，提高组件开发效率和代码可维护性。

- 使用 TypeScript 提供静态类型约束，统一定义用户、电影、评论、任务、权限等数据类型，减少前后端数据交互过程中的类型错误。

- 使用 Vite 作为前端构建工具，提供快速的开发启动和构建能力。

- 使用 Vue Router 实现单页应用路由管理，系统划分为登录注册页面、用户端页面和管理端页面，并通过路由守卫实现登录校验和权限控制。

- 使用 Pinia 进行状态管理，主要维护用户登录状态、令牌信息、用户权限、电影列表和筛选条件等全局状态。

- 使用 Element Plus 构建前端界面，包括表单、表格、分页、弹窗、通知、标签、上传等常用交互组件，提高页面开发效率和交互一致性。

- 使用 Axios 封装 HTTP 请求，统一处理接口地址、请求头、身份令牌和异常响应，使组件不直接依赖底层请求实现。

- 使用 ECharts 和 echarts-wordcloud 实现评论词云可视化，使电影评论数据能够以更直观的方式呈现。

- 使用 vue-cropper 实现头像和电影海报的图片裁剪，提高上传图片的展示质量。

### 2. 后端技术栈

- 后端采用 Quart 作为 Web 框架。Quart 是兼容 Flask 风格的异步 Web 框架，适合处理异步数据库访问、后台任务调度和 WebSocket 通信等场景。

- 使用 Python asyncio 构建异步执行模型，配合后台 Puller、Worker 和 Monitor 协程实现爬虫任务调度、任务执行和系统监控。

- 使用 quart-schema 和 Pydantic 进行请求参数、响应数据和配置项建模，提高接口数据结构的规范性和可靠性。

- 使用 Hypercorn 作为 ASGI 服务运行容器，支撑异步 HTTP 服务和 WebSocket 服务。

- 使用 PyJWT 实现基于 JWT 的身份认证，结合 bcrypt 对用户密码进行安全哈希存储。

- 使用自定义权限模型实现细粒度访问控制，将用户管理、电影管理、评论管理、爬虫任务、基础设施管理、系统监控等操作拆分为不同权限点。

- 使用统一异常处理和结构化日志机制，对业务异常、认证异常、权限异常、数据库异常和爬虫异常进行统一封装，方便前端展示和后端排查。

### 3. 数据库与缓存技术栈

- 使用 MySQL 存储核心结构化业务数据，包括用户、权限、电影基础信息、演职人员、地区、类型、评分、任务历史、失败任务等。

- 使用 aiomysql 构建异步 MySQL 连接池，并通过参数化查询降低 SQL 注入风险。

- 使用 MongoDB 存储长评和短评等文本型、半结构化数据，适合评论内容字段灵活、数据量较大的业务场景。

- 使用 motor 作为 MongoDB 异步驱动，使评论查询和写入能够融入后端异步调用链路。

- 使用 Redis 承担延迟任务队列、接口限流、任务去重和词云缓存等功能，提高系统吞吐能力和后台任务调度效率。

- 使用 Redis ZSET 实现延迟队列，通过分数记录任务执行时间，使爬虫任务能够按照计划时间有序调度。

### 4. 爬虫与后台任务技术栈

- 使用 Playwright 作为浏览器自动化工具，支持对动态网页内容进行访问和解析，适用于需要浏览器环境的电影信息采集场景。

- 使用 aiohttp 作为异步 HTTP 请求工具，适用于部分接口化或轻量级数据请求场景。

- 爬虫模块划分为抓取、解析、存储、代理管理、Cookie 管理、身份管理和失败处理等子模块，降低模块耦合度。

- 系统通过代理池和 Cookie 池维护多个访问身份，并结合状态机管理可用、可疑、禁用等状态，提高爬虫运行稳定性。

- 后台任务执行过程中通过任务历史表和失败任务表记录执行结果，实现任务可追踪、失败可恢复、问题可定位。

### 5. 部署与运行支撑

- 项目采用前后端分离结构，前端通过 Vite 构建静态资源，后端提供 REST API 和 WebSocket 服务。

- 系统提供 Dockerfile 和 docker-compose 配置，可将前端、后端、MySQL、MongoDB、Redis 等组件进行容器化部署。

- 使用 Nginx 承载前端静态资源并反向代理后端接口，便于统一入口、跨域处理和生产部署。

- 系统内置日志、系统状态监控、队列状态监控、限流状态查看等能力，便于运维人员了解系统运行情况。

## 四、摘要精简版

本文设计并实现了一套基于前后端分离架构的电影数据管理与展示系统。系统面向电影信息聚合、影评数据管理和后台爬虫调度场景，提供用户注册登录、电影浏览检索、电影详情展示、长短评查看、评论词云分析、个人资料维护等用户端功能；同时提供电影数据维护、评论审核、用户权限管理、豆瓣 ID 管理、爬虫任务调度、失败任务处理、代理与 Cookie 管理、系统监控等管理端功能。系统通过后台异步任务机制实现电影基础信息、评分、演职人员、长评和短评等数据的自动化采集，并通过任务历史、失败记录、实时通知和状态监控提升数据采集过程的可靠性与可追溯性。

在技术实现方面，前端采用 Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus 和 ECharts 构建单页应用，实现模块化页面开发、权限路由控制和评论数据可视化展示。后端采用 Quart、Python asyncio、Pydantic、JWT 和 WebSocket 构建异步 Web 服务，结合 Playwright 和 aiohttp 实现网页数据采集。数据层采用 MySQL、MongoDB 和 Redis 的组合架构，其中 MySQL 用于存储用户、权限、电影和任务等结构化数据，MongoDB 用于存储长评和短评等半结构化文本数据，Redis 用于任务队列、限流、去重和缓存。系统整体具有较好的模块化、可扩展性和运行可观测性，能够满足电影数据采集、管理与展示的一体化需求。
