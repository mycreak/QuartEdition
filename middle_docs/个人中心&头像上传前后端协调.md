## 一、后端必做改造清单（优先级从高到低）
### 1. 数据库改动（优先级：高）
```sql
ALTER TABLE `users` 
ADD COLUMN `avatar_url` VARCHAR(2048) DEFAULT '' COMMENT '用户头像TOS签名URL' AFTER `display_name`;
```
> 说明：空字符串表示用户未上传头像，前端自动展示默认占位头像

### 2. 现有接口扩展（优先级：高）
| 接口 | 改动说明 |
|------|----------|
| `GET /auth/me` | 响应的`User`对象新增`avatar_url`字段，返回带签名的TOS临时URL（有效期24h，遵循TOS签名规范） |
| `PATCH /admin/users/<id>` | 扩展支持接收`avatar_url`参数，允许管理员修改其他用户的头像，权限校验保持原有`user:manage`不变 |

### 3. 新接口：用户自编辑接口（优先级：高）
`PATCH /auth/me` — 登录用户修改自己的个人信息
> 权限要求：登录即可访问，不需要额外权限

### 4. 新接口：头像上传接口（优先级：高）
`POST /upload/avatar` — 上传用户头像到TOS并返回URL
> 权限要求：登录即可访问，每个用户只能上传自己的头像

***

## 二、接口详细定义
### 1. PATCH /auth/me
#### 请求参数
```json
{
  "display_name": "新昵称（选填，长度1-64位）",
  "avatar_url": "新头像TOS URL（选填，空字符串表示清空头像）"
}
```
#### 响应示例
```json
{
  "success": true,
  "message": "更新成功",
  "data": {
    "id": 1,
    "username": "user123",
    "display_name": "新昵称",
    "avatar_url": "https://xxx.tos-cn-beijing.volces.com/avatars/avatar_xxx.jpg?sign=xxx",
    "is_active": true,
    "permissions": ["xxx"]
  }
}
```
#### 错误码
| 状态码 | 错误信息 | 说明 |
|--------|----------|------|
| 400 | 昵称格式不正确 | 昵称长度超出限制或包含非法字符 |
| 401 | 未登录 | 登录过期或token无效 |

---

### 2. POST /upload/avatar
#### 请求参数
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file` | File | ✅ | 上传的头像文件 |
> Content-Type: multipart/form-data
#### 校验规则
- 文件大小：最大2MB
- 文件格式：仅支持`image/png`/`image/jpeg`/`image/webp`
- 自动裁剪为200x200正方形（建议后端裁剪，也可以前端裁剪后上传）
#### 响应示例
```json
{
  "success": true,
  "message": "上传成功",
  "data": {
    "avatar_url": "https://xxx.tos-cn-beijing.volces.com/avatars/avatar_${user.uuid}.webp?sign=xxx"
  }
}
```
#### 存储规则
- TOS对象Key固定格式：`avatars/avatar_${user.uuid}.webp`，同一个用户上传直接覆盖旧文件
- 自动转成WebP格式压缩，节省存储空间
#### 错误码
| 状态码 | 错误信息 | 说明 |
|--------|----------|------|
| 400 | 文件大小超过限制（最大2MB） | 上传文件过大 |
| 400 | 不支持的文件格式，仅支持png/jpg/webp | 格式非法 |
| 401 | 未登录 | 登录过期或token无效 |
| 500 | 上传失败，请稍后重试 | TOS服务异常或内部错误 |

## 三、验收标准
### 功能验证点
✅ 普通用户调用`PATCH /auth/me`可以修改自己的昵称和头像，修改后`GET /auth/me`返回最新值  
✅ 上传的头像URL可以正常在浏览器访问，格式为带签名的TOS URL  
✅ 管理员调用`PATCH /admin/users/<id>`可以修改任意用户的头像  
✅ 未上传头像的用户`avatar_url`返回空字符串，前端自动展示默认占位头像  
✅ 上传超过2MB的文件、非图片格式文件会返回对应错误提示

### 兼容要求
- 旧版本客户端无感知，新增字段不影响原有功能
- 头像上传接口可以兼容前端裁剪后上传和后端裁剪两种模式
- 签名URL机制和现有海报签名逻辑完全一致，不需要前端额外适配
