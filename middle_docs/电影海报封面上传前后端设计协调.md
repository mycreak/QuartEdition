# 电影海报封面上传 — 前后端设计协调文档
> 最后更新：2026-05-14

## 一、需求概述
管理员可以在电影详情页上传本地海报图片，替代当前仅支持粘贴URL的方式，上传后自动存储到火山引擎TOS图床，获得可直接访问的URL。

---

## 二、现状与差异

| 对比项 | 当前 | 目标 |
|--------|------|------|
| 海报来源 | 粘贴外部URL | 上传本地图片 + 可继续粘贴URL |
| 图片处理 | 无 | 裁剪 + 压缩 + 转webp |
| 存储 | 外部链接，不可控 | 火山引擎TOS，图床可控 |
| 交互体验 | 文本框输入 | 点选文件 → 裁剪 → 确认上传 |

---

## 三、前端设计

### 3.1 组件设计
复用现有的`AvatarUpload.vue`的模式，新增`PosterUpload.vue`组件：

```
PosterUpload.vue
├── 海报展示区（当前poster_url预览，含错误回退占位图）
├── 触发按钮（hover遮罩层显示「更换海报」）
├── 隐藏的input[type=file]（accept: png/jpg/webp，限制5MB）
├── 裁剪弹窗（vue-cropper，16:9宽高比）
└── 上传进度反馈（loading状态 + 成功/失败提示）
```

### 3.2 上传流程
```
① 管理员点击海报区域
    ↓
② 系统弹出文件选择器（限制png/jpg/webp，≤5MB）
    ↓ 校验不通过
③ 弹出裁剪弹窗（vue-cropper，固定16:9比例，可缩放/移动）
    ↓
④ 管理员确认裁剪
    ↓
⑤ 前端生成裁剪后的Blob（webp格式，quality=0.8）
    ↓
⑥ 调用后端接口 POST /upload/poster（multipart/form-data）
    ↓ 后端处理
⑦ 返回图床URL → 前端回填到表单 → 海报展示区实时更新
```

### 3.3 交互细节
- **裁剪比例**：16:9（电影海报标准比例）
- **文件大小限制**：5MB（海报分辨率高，比头像限制大）
- **支持格式**：png / jpg / webp，上传时统一转为webp
- **粘贴URL功能保留**：管理员仍可手动输入外部URL，组件同时支持两种模式
- **错误后回退**：上传失败时保留原图不丢失，仅显示错误消息

## 四、后端接口需求

### 4.1 新增上传端点

```
POST /upload/poster

认证: Bearer JWT（需要 movie:manage 权限）
请求: multipart/form-data
  - file: 图片文件（png/jpg/webp，≤5MB）

响应 200:
{
  "success": true,
  "data": {
    "poster_url": "https://movie-poster.tos-cn-guangzhou.volces.com/covers/xxx.webp"
  }
}

响应 400:
{ "error": "参数校验失败: 文件大小不能超过5MB" }
{ "error": "参数校验失败: 仅支持png/jpg/webp格式" }

响应 403:
{ "error": "权限不足" }
```

### 4.2 技术实现建议
- **存储路径**：`covers/` 目录（与现有海报URL路径一致）
- **文件命名**：`{douban_id}_{timestamp}.webp` 或 UUID 方式，避免文件名冲突
- **图片处理**：服务端不再二次处理，由前端裁剪后上传，减少后端开销
- **权限**：复用 `movie:manage` 权限，和编辑电影信息保持一致

### 7.3 后端实现方案

#### 新文件：`routes/admin/poster_routes.py`
```
端点: POST /upload/poster
权限: movie:manage
蓝图: poster_bp（挂载到 app 根路径）
```

#### 注册方式：`app.py`

```python
from routes.admin.poster_routes import poster_bp
app.register_blueprint(poster_bp)  # 挂载到根路径 → POST /upload/poster
```

（不与 `/admin` 或 `/user` 冲突，因为海报上传无需 url_prefix）

#### 处理逻辑

```
POST /upload/poster  (multipart/form-data, field=file)
  │
  ├─ require_permission("movie:manage")  → 403 如果权限不足
  │
  ├─ 校验文件 ≤ 5MB                      → 400 超限
  ├─ 校验格式 png/jpg/webp              → 400 格式不支持
  │
  ├─ 生成 key: covers/movie_{timestamp}_{6位随机}.webp
  │    （前端已裁剪，后端只管存，不二次处理）
  │
  ├─ tos.upload(key, data, "image/webp") → TOS
  │
  └─ 返回 { success, data: { poster_url } }
```

### 7.4 关键设计决策

| 决策 | 理由 |
|------|------|
| **文件名用时间戳+随机数** | 同一电影可多次上传不冲突；无需传 `movie_id`/`douban_id` |
| **接口不传 movie_id** | 前端拿到 URL 后自行回填到编辑表单，后端只负责存储 |
| **不二次裁剪** | 前端 `vue-cropper` 已按 16:9 裁剪并转 webp，后端存原样 |
| **挂载根路径非 `/admin`** | 和头像上传 `/user/upload/avatar` 保持对等设计 |
| **复用 `POSTER_MAX_SIZE_MB`** | 已有配置项，不重复定义 |
| **复用 `movie:manage` 权限** | 和编辑电影信息保持一致，不新增权限码 |
